# ADR-001：Glossary 采用自定义 Trie 实现（不使用 pyahocorasick）

- **状态**：已采纳
- **日期**：2026-05-16
- **决策**：Glossary 引擎采用基于字典的手写 Trie 实现，不依赖 pyahocorasick 等外部 Aho-Corasick 库。
- **理由**：LocalCAT 核心层（L1-L3）必须仅使用 Python stdlib。pyahocorasick 为第三方 C 扩展，引入它将违反 stdlib-only 约束，且增加本地部署的编译依赖风险。自定义 Trie 在当前数据规模下性能可接受，且完全可控。
- **约束**：Glossary 的匹配性能取决于 Trie 实现质量。若未来需要更高性能的多模式匹配（如大规模术语表 + 长文本流），可能需要在 L4 层引入外部库作为可选加速，但 L2 层的 Trie 实现必须保留作为 fallback。
- **来源**：tech.md + glossary_engine.py
