# ADR-002：TM 采用 JSONL Append-Only 存储并使用 Last-Write-Wins 冲突策略

- **状态**：已采纳（部分被 ADR-007 取代）
- **日期**：2026-05-16
- **被取代于**：ADR-007
- **取代范围**：已激活资源的 canonical runtime 存储、索引与查询 authority
- **保留范围**：never-activated、首次激活取消/失败且尚无 canonical generation 的 legacy JSONL exact-only 行为，以及本 ADR 的历史背景
- **决策**：Translation Memory 以 JSONL（JSON Lines）格式存储，采用 append-only 写入模式（仅追加，不修改已有记录），并以 Last-Write-Wins（LWW）策略处理翻译单元冲突——同一源文的多次翻译，以最后写入的条目为准。
- **理由**：JSONL 是纯文本行格式，天然支持 append-only 写入，无需读取-修改-写入循环，降低存储层复杂度和数据损坏风险。LWW 策略与 append-only 模型一致：不做冲突合并，只认最后一条，逻辑简单、行为可预测。两者组合确保 TM 存储是 append-only + 无合并的单向数据流。
- **约束**：(1) TM 文件只增长不缩小，需要外部机制处理文件大小管理（如 compact/归档）。(2) LWW 意味着历史翻译会被静默覆盖（在查询层），若需翻译溯源必须通过 JSONL 的完整追加历史回溯。(3) JSONL 不是结构化查询格式，大规模 TM 的随机访问性能依赖于内存索引（见 ADR-006）。
