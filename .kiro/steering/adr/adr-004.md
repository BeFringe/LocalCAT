# ADR-004：Parser 子系统对 Engine 层的单向依赖

- **状态**：已取代（由 ADR-015 取代）
- **日期**：2026-05-16
- **取代日期**：2026-08-21
- **决策**：Parser 子系统（Layer 2B）可以依赖 Core Engine（Layer 2A）的接口和数据模型，但 Core Engine 绝不依赖 Parser 子系统。依赖方向为 Parser → Engine，永远不允许反向。
- **理由**：Core Engine（Trie、TM 匹配）是系统的计算核心，必须保持稳定和独立。Parser 子系统是数据入口，职责是将外部格式转换为 Engine 可处理的内部数据模型。如果 Engine 依赖 Parser，就会引入格式感知——Engine 需要知道数据"从哪来"，违反了分层架构的"向下依赖"原则。单向依赖确保 Engine 保持格式无关性。
- **约束**：(1) Parser 模块可以 import Engine 层的 data model 和 interface，但 Engine 模块不得 import 任何 Parser 层的符号。(2) 未来新增 Parser 类型（如 XLIFF、TMX）时，只能依赖 Engine 层已有接口，不能为适配新 Parser 而修改 Engine。(3) 若发现 Engine 需要 Parser 的信息，说明抽象边界有误，需重新设计数据流向。
