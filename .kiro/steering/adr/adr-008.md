# ADR-008：TM generation 通过 sealed/active 内容证明链原子发布

- **状态**：已采纳
- **日期**：2026-08-16
- **采纳日期**：2026-08-17
- **背景**：SQLite 文件可在 schema/count 不变时发生语义篡改，单纯的文件存在、`integrity_check` 或调用方自报布尔值不能证明待发布内容与已验证语义属于同一个时代。迁移、schema upgrade 与崩溃恢复使用 generation sealed→active 发布链；合法 append 共享同一 authority/attestation 约束，但不重新执行 generation replace 生命周期。
- **决策**：
  1. mutable stage 只能由 `StageSealer` 在 commit+fsync 后完成 integrity、authority/candidate projection、semantic closure 与 terminal file-proof 复验，并铸造一次性 sealed registration capability。
  2. 激活必须以 sealed attestation、DB/manifest/source 绑定和 durable journal 为输入，在 generation 发布前完成原子 replace、fsync 与最终语义验证。
  3. 当前本地 SQLite profile 的 active attestation 只可在 exact inode+bytes+phase 不变时复用。长期治理不把 POSIX inode 泛化为所有平台唯一抽象；若平台文件身份机制改变，必须另经 ADR 与等价反例验证，且不得弱化“稳定文件身份 + 精确内容 + 阶段”不变量。
  4. 合法 append 不重新执行 generation replace/`StageSealer`，但必须共享 attestation 失效、head/content 重验、lease 隔离和 fail-closed 语义；不得按 generation 名称盲目缓存。
  5. concrete registry reserve/commit 不是外部便捷入口；只有 `StageSealer` 完成 post-fsync projection、closure 与 terminal proof 后铸造的单次 capability 才可注册。
  6. operation lease 保护 generation 替换与查询视图生命期；任何绑定、阶段、文件身份或语义闭包漂移均 fail-closed。
- **后果**：发布权威从可替换的文件路径提升为内容、语义、阶段和 generation 成套证明。generation replace 与 append 具有不同生命周期，但共享同一 authority/attestation 安全边界。代价是封存/激活协议更严格，且便捷注册路径不再对外开放。
