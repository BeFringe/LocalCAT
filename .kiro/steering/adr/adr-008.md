# ADR-008：TM generation 通过 sealed/active 内容证明链原子发布

- **状态**：草案（实现已落地，待治理确认）
- **日期**：2026-08-16
- **背景**：SQLite 文件可在 schema/count 不变时发生语义篡改，单纯的文件存在、`integrity_check` 或调用方自报布尔值不能证明待发布内容与已验证语义属于同一个时代。迁移、schema upgrade、崩溃恢复与合法 append 还需要共享同一发布边界。
- **决策**：
  1. mutable stage 只能由 `StageSealer` 在 commit+fsync 后完成 integrity、authority/candidate projection、semantic closure 与 terminal file-proof 复验，并铸造一次性 sealed registration capability。
  2. 激活必须以 sealed attestation、DB/manifest/source 绑定和 durable journal 为输入，在 generation 发布前完成原子 replace、fsync 与最终语义验证。
  3. active attestation 只可在 exact inode+bytes+phase 不变时复用；合法 append 或任何内容变化必须进入新的权威验证，不得按 generation 名称盲目缓存。
  4. operation lease 保护 generation 替换与查询视图生命期；任何绑定、阶段、文件身份或语义闭包漂移均 fail-closed。
- **后果**：发布权威从可替换的文件路径提升为内容、语义、阶段和 generation 成套证明。代价是封存/激活协议更严格，且便捷注册路径不再对外开放。
