# ADR-009：运行时能力由独立证据门发布，消费者默认 fail-closed

- **状态**：草案（实现已落地，待治理确认）
- **日期**：2026-08-16
- **背景**：文本匹配、context 与 fuzzy 检索的可用性依赖语义版本、golden/oracle、存储健康和性能门。如果调用方从某个 JSON 中的 `PASS`、类是否存在或局部测试自行推断能力，就会形成多个授权权威。
- **决策**：
  1. matcher、context 和 fuzzy 的 evidence 解析、时间窗、source fingerprint、oracle/benchmark 与资源健康复核属于 Core owner。
  2. Core 只向消费者发布一次性、不可变的 capability snapshot 和 capability-gated service port；默认 publisher 必须是 `UNAVAILABLE`。
  3. composition root 负责用已验证 Core owner 装配 `CapabilityGatedTextMatcher` 与 `TMRetrievalService`。UI、Controller、Glossary 或测试夹具不得解析 evidence JSON、构造替代 publisher 或从部分 PASS 推断更高能力。
  4. 任一 evidence、build、semantics、fixture、resource binding 或有效期不闭合时，只能按已冻结规则降级或关闭相应能力，不得由上层 fallback 绕过。
- **后果**：证据是 Core 的授权输入，而不是 UI 的配置文件。上层组合更简单且失效语义一致；代价是正式运行必须有明确的 composition-root 装配。
