# ADR-009：运行时能力由独立证据门发布，消费者默认 fail-closed

- **状态**：已采纳
- **日期**：2026-08-16
- **采纳日期**：2026-08-17
- **背景**：文本匹配、context 与 fuzzy 检索的可用性依赖语义版本、golden/oracle、存储健康和性能门。如果调用方从某个 JSON 中的 `PASS`、类是否存在或局部测试自行推断能力，就会形成多个授权权威。
- **决策**：
  1. matcher、context 和 fuzzy 的 evidence 解析、时间窗、source fingerprint、oracle/benchmark 与资源健康复核属于 Core owner。
  2. Core publisher 可在正式验证后原子刷新；每个 operation/query 必须只捕获一次 immutable capability snapshot，并在该次操作内保持一致。默认 publisher 必须是 `UNAVAILABLE`。
  3. Feature 5 当前交付 evaluator、publisher 与 gated service seams；application composition root 必须显式装配 `CapabilityGatedTextMatcher` 与 `TMRetrievalService`，不得把“已有 seam”写成“应用装配已经完成”。
  4. matcher 正式路径必须依赖已验证 manifest；缺失证据时显式发布 unavailable。retrieval 使用明确的 default-unavailable publisher。UI、Controller、Glossary 或测试夹具不得解析 evidence JSON、构造替代 publisher 或从部分 PASS 推断更高能力。
  5. UI 可以显示 capability 的 non-authoritative 安全投影，但不得持有 evaluator、解析 evidence 或反向铸造 capability。
  6. 任一 evidence、build、semantics、fixture、resource binding 或有效期不闭合时，只能按已冻结规则降级或关闭相应能力，不得由上层 fallback 绕过。
- **后果**：证据是 Core 的授权输入，而不是 UI 的配置文件。每次操作得到一致快照，publisher 仍可在验证后刷新；代价是正式运行必须有明确的 application composition-root 装配。
