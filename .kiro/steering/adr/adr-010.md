# ADR-010：fuzzy 完备性由有界候选证明授权，FTS/回退只选择性能路径

- **状态**：已采纳
- **日期**：2026-08-16
- **采纳日期**：2026-08-17
- **背景**：仅依赖 FTS 命中、固定 candidate limit 或组件启发式无法证明 threshold 结果和 top-k 完备。对 100k TM 执行无界真实 scorer 又不满足可预测的延迟与资源上限。
- **决策**：
  1. fuzzy candidate session 必须以可验证上界和严格 frontier 证明 threshold/top-k 闭合，并保持 `真实分数 <= U4 <= U3 <= U2 <= U1`。
  2. exact Unicode code-point LCS 只收紧编辑距离下界并形成 U3/U4；不计算 Levenshtein/final score，不建立 scorer 等价类。
  3. 证明分别保守 all-accounted、raw-distinct ranking 与 exact-fold scorer invocation 三个身份域，不得混用。当前 `candidate-budget-v1 = min(8192, max(2048, result_limit * 128))`；top-k 不超过 16（包括冻结 top-10）时预算为 2048，版本绝对上限为 8192，单批不超过 32。
  4. FTS5 trigram 与 gram fallback 只是确定性性能选择。两路必须共用同一 proof state machine、scorer、threshold、top-k 和 oracle；任一路径的命中或排名不能自行授权 completeness。
  5. 当前 v3 production completion 可由 threshold 全闭合，或“已有 k 个 threshold-qualified raw-distinct identity，且真实第 k 名严格支配全部未评分 frontier”闭合；`oracle_full` 仍要求 threshold 与 top-k 两项全局闭合，tie equality 必须继续竞争。
  6. ordered projection、receipt、generation/head/count/query binding 或身份守恒发生缺失、重复、乱序、篡改或 race 时，整个资源查询 fail-closed；预算耗尽前不得产生部分可见 mutation。
  7. `proof-query-v3`、U1/U2/U3/U4、P1/P2/P3、ordered receipt 与 batch profile 是当前 Core 版本合同；UI 不复制、不控制，也不将它们暴露为普通产品设置。公开 UI payload 也不得泄露正文、fold、LCS、gram 或等价键等证明材料。
- **后果**：fuzzy 查询的性能优化不再与正确性授权混同，可对每个未评分 identity 说明为何不会进入结果。预算是 versioned query profile 而非固定 2048。代价是查询合同和反篡改测试显著增加。
