# ADR-011：Feature 5 与 UI 通过 Qt 无关冻结合同和 Controller adapter 集成

- **状态**：已采纳
- **日期**：2026-08-16
- **采纳日期**：2026-08-17
- **背景**：Feature 5 `TMResult` 强制区分 `query_source` 与 `matched_source`，并将 match type、similarity、context/provenance 与稳定排序绑定在同一结果。现有 UI `TMSuggestion` 只有一个 `source`；如果 adapter 将两个 source 折叠，fuzzy 展示、过期应用保护与用户解释都会丢失。
- **决策**：
  1. Core 拥有 `SearchOptions`、matcher capability/request/outcome、`TMResult` 及 exact/context/fuzzy 分数与排序语义；UI 不复制 case-fold、Whole Word、CJK、scorer 或候选逻辑。
  2. UI frozen contract 必须在接入 fuzzy 前分开表达 `query_source` 与 `matched_source`，并至少保留 resource/record identity、target、match type、final similarity、安全 provenance 投影和用于拒绝 stale apply 的 query/current-segment identity；不得用旧的单 `source` 形状静默压缩 Core 结果，也不得泄露 raw `SimilarityEvidence` 或 proof metadata。
  3. Qt 无关 application composition root 解析 declarative `ResourceConfig`，取得 canonical/legacy Core port，构造 `TMResourceHandle`/`TMQuery`，并装配正式 matcher/retrieval publisher。legacy 资源只能取得 exact-only port，不能因 mixed 模式被提升为 fuzzy。
  4. Qt 无关 Controller adapter 消费 Core `QueryReport`，映射 UI `TMSuggestion` 与 resource-status projection；它不承担 capability 证明，也不让 composition root 负责展示 DTO。
  5. Layer 4 只调用 `EditorController` 并渲染 UI contract；Qt 模块不导入 SQLite store、scorer、retrieval、evidence evaluator、candidate proof 或 Feature 5 内部实现。
  6. UI 拥有资源显示名、交互状态、建议展示与显式应用；Core 记录/资源身份和证据不由 UI 重新授权。resource-local failure 映射为独立安全状态/警告，不伪造成 suggestion，也不吞掉其他资源成功结果。
  7. 默认 publisher、调用方布尔值、局部 `PASS` 或 FTS 可用性均不得开放 fuzzy。closed/stale capability 与 mixed legacy/canonical 必须诚实投影为 exact-only、degraded 或 unavailable，不能静默伪装成“没有匹配”。
  8. 本 ADR 只冻结跨层边界，不自动扩大任一 Feature Spec 的实施范围；fuzzy UI 落地仍需相应 Requirements/Design/Tasks 的显式修订与人工批准。
- **后果**：UI 可在不成为第二 TM 权威的前提下展示可解释 fuzzy 建议。第一个集成任务必须先升级 `TMSuggestion` 冻结合同，再分别建立 composition root 与 Controller adapter，不能从 Qt 控件直接下钻到 SQLite。
