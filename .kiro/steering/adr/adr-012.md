# ADR-012：未发布的首次激活残留不构成 canonical authority

- **状态**：已采纳
- **日期**：2026-08-19
- **采纳日期**：2026-08-19
- **决策 owner**：LocalCAT 项目 owner
- **关联 Spec**：`tm-storage-retrieval-index` Requirement 2；`feature5-ui-integration` Requirement 5 / Task 2.5

## 背景

首次 canonical 激活可在 mutable SQLite stage 构建期被进程退出中断。此时目录中可能留下 salted `.sqlite3.stage` 及 SQLite `-journal`，但尚无 sealed registration、canonical sidecar、snapshot manifest、durable activation journal/terminal 或 lineage marker。

当前 Task 2.5 实现将任意匹配 stage family 的残留同时视为 cleanup 不可证明和 canonical authority 不可证明，返回 `canonical_authority_ambiguous=True`。运行时 resolver 却正确地只从 durable publication facts 判定 authority，因而仍观察到 legacy exact-only。这一分类矛盾会使 Controller 把单个资源的激活失败扩大为整个 TM cohort 的 `TM.ACTIVATION.RUNTIME_REFRESH_FAILED`，关闭其他健康 legacy exact 查询。

## 决策

决策如下：

1. 没有 live resource reservation，且不存在 canonical sidecar、snapshot manifest、durable activation journal/terminal 或 lineage marker 时，salted first-activation mutable stage residue 不是 canonical authority fact。
2. 对这类 orphan residue，系统继续以原 JSONL 作为 never-activated legacy exact-only authority，并允许新的 fresh-nonce initial activation 重试。
3. 新尝试不得打开、跟随、删除、移动或复用旧 residue；旧 regular file、hardlink、symlink 及 SQLite journal 的 inode/bytes 保持不变。
4. 任何已可观察的 durable publication/recovery fact，以及 PREPARED 后无法完整回滚或重演的状态，继续 fail-stop 为 unavailable，不允许 legacy fallback。
5. orphan cleanup 是独立 maintenance 问题。若未来要自动归档或删除，必须另行设计持久 attempt ownership/tombstone 与恢复协议，不得从文件名推导所有权。

## 长期约束

- mutable stage 只有通过 ADR-008 的 seal + durable publication 链才能影响 canonical authority。
- cleanup 可证明性与 authority 可证明性必须分开表达；无法安全删除未知 inode 不能自动提升为“可能已发布”。
- Controller 对真正 ambiguous/published-unavailable authority 的全局 fail-closed latch 保持不变；修复必须发生在 Core 分类边界。
- 任何重试都使用新的不可预测 namespace，不让旧 candidate 进入新发布链。

## 后果与权衡

用户可在应用异常退出后继续使用 legacy exact，并重新发起 canonical 激活；其他 TM 不再因一个 unpublished orphan 被全局关闭。代价是旧 stage 可长期占用本地磁盘，直至有独立、可证明所有权的 maintenance 协议。

## 备选方案

- **继续将任意 salted residue 视为 authority ambiguous**：被拒绝。它把 unpublished work artifact 提升为第二 authority fact，并与运行时 durable-facts resolver 矛盾。
- **resolver 看到 stage 就返回 unavailable**：被拒绝。它会让 mutable candidate 改变 query authority，且无法恢复 never-activated legacy 语义。
- **自动删除或移动 residue**：本候选不授权。现有文件名和目录事实不足以证明跨进程所有权。
- **只在 Controller 屏蔽目标资源**：被拒绝。它不能修复重启后的 Core 分类，也会削弱真正 ambiguity 的 fail-stop 边界。
