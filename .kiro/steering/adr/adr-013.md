# ADR-013：Gate D 跨进程证据重授权模型

- **状态**：已采纳
- **日期**：2026-08-19
- **决策 owner**：LocalCAT 项目 owner
- **关联 Spec**：`tm-storage-retrieval-index` Requirement 8；`feature5-ui-integration` Requirement 6 / Task 3.6 / Qt TM surfaces

## 背景

当前 Qt composition 在每个进程中重新执行 Matcher Gate → Gate C → Gate D。Gate D 为两条 intended path 运行 literal oracle 与 100,000-record migration/query/latency；本机 current-source 实测约 540.5 秒。主线程未被阻塞，但 FUZZY 在整个窗口内必须关闭。

仓库已跟踪与当前 implementation fingerprint 匹配的 `benchmark_tm_evidence.json`，但现有发布协议只接受本进程 Core owner 在新 absent evidence path 上完成真实运行后铸造的一次性 receipt。严格 codec、digest 和 implementation fingerprint 能证明 bundle 内部一致，不能单独证明它由某次受信真实执行产生。

## 决策

采用“同设备持久资格自动恢复 + 显式手动重新验证”：

1. Gate D 的资格作用域是设备与 retrieval implementation epoch，不是项目或某一份 TM。项目/TM 内容未变、Lookup/Update 配置改变，均不能单独铸造或撤销 Gate D 资格。
2. 应用启动不得自动实跑 Gate D。若存在可验证的本设备 attestation 且 compatibility key 完全相同，Core 自动重授权并直接恢复 FUZZY 卡片；该恢复不要求用户等待或点击同步。
3. 若没有可验证的本设备 attestation，或 compatibility key 已失配，Exact/Context 保持各自当前能力，FUZZY fail-closed；UI 提供显式“重新验证 Fuzzy 性能资格”操作，不在后台静默开始 100k 运行。
4. “重新验证”必须由当前进程 Core owner 真正运行既有 Gate D oracle/100k intended paths，并在成功 publication 的同一事务尾部铸造设备本地 attestation；它不是导入、复制或信任 tracked `benchmark_tm_evidence.json`。
5. 后续进程只能由 Core 验证并重授权该 attestation。Qt、Controller 和 application cache 不得解析 bundle 后自行开放 FUZZY，也不得从 `RUNNING/SUCCEEDED` 展示状态推断 capability。
6. compatibility key 至少绑定 device identity、implementation fingerprint、benchmark/proof version、Gate C build/semantics/fixture/evaluator identity、Python/SQLite/Unicode/platform 与 intended-path identity。普通 TM 导入/追加/删除、Active/Lookup/Update 配置、项目切换和 canonical resource generation 不进入 key；只有它们伴随 index schema、rebuild protocol 或检索后端变化时，才通过对应实现身份使 key 失效。任一字段不匹配、attestation 损坏/缺失/篡改，只关闭 FUZZY，不撤销 exact/context。
7. UI 可以提供默认开启的“使用已验证的 Fuzzy 建议”偏好。关闭它只能收窄当前能力；重新开启仍须 Core 已持有有效 attestation，不得成为绕过 Gate C/D 的授权开关。
8. device-local provenance 定义为当前本地用户 profile 下的 Core-owned `0700` 状态目录、独立 `0600` 32-byte 随机设备密钥、完整 strict evidence bundle 与 canonical envelope 的 HMAC-SHA256。attestation 以 `0600` 临时文件 fsync 后原子替换并 fsync 目录；restore 必须 no-follow 读取、复核 owner/mode/nlink、strict schema/HMAC/bundle/artifact/compatibility，再由 Core 私有 factory 重铸一次性 run receipt。普通 JSON digest 或 implementation fingerprint 本身不构成 provenance。
9. attestation 不设日历有效期；实现、Gate C 身份、benchmark contract/proof、Python/SQLite/Unicode/platform 或本地设备密钥任一变化即失效。用户可以随时显式重新验证并原子替换资格。损坏、缺失、失配或权限异常均只关闭 FUZZY 并显示“需重新验证”，不自动清理未知文件，也不撤销 exact/context。
10. 本模型防止普通缓存损坏、非授权替换和仅凭自洽 JSON 重铸；已完全接管同一系统用户文件与进程的攻击者不在本地桌面威胁模型内。设备资格的精确作用域因此是受该用户 profile 私有密钥约束的本机运行环境，而不是可随项目复制的资源文件。

## 长期约束

- Gate C fuzzy-core 与 Gate D intended-path 资格继续是独立 authority；缓存只能优化 Gate D 证明生命周期，不能替代 Gate C。
- FUZZY 只在 Core 对完整兼容性和 provenance 复证后才可发布；缓存损坏或失效只能 fail closed。
- Qt 只消费 Controller 安全投影，不得依赖 benchmark/evidence/receipt 实现。
- 新协议必须保留旧在途 query 的 immutable snapshot 和 Gate C/D publication 原子性。

## 后果与权衡

该决策取消每次冷启动约九分钟的自动等待，并保留“当前设备确实完成性能硬门”的原语义。代价是首次或 compatibility key 失效后，FUZZY 会保持关闭直至用户显式重新验证；设备私有密钥与 attestation 成为新的本地持久化恢复协议。

## 备选方案

- **继续每进程重跑**：当前已授权的基线，安全但产品等待过长。
- **发布流程签发、所有设备直接复用**：本候选不采用。它不能证明当前设备满足既有性能硬门，若未来需要必须另行取代本决策。
- **直接复用 tracked `benchmark_tm_evidence.json`**：被拒绝。它缺少可重铸 receipt 的 provenance，并违反当前 frozen protocol。
- **只按 digest/fingerprint 信任 application cache**：被拒绝。内部自洽不是真实执行证明。
- **只改 UI 文案**：可作为独立的无 ADR 短期补救，但不解决冷启动耗时。
