# ADR-016：已发布 canonical authority 的设备身份重新证明

- **状态**：已采纳
- **日期**：2026-08-21
- **决策 owner**：LocalCAT 项目 owner
- **关联 Spec**：`feature5-ui-integration` Requirement 5 / Task 6.7；`tm-storage-retrieval-index` activation recovery

## 背景

canonical TM 的 active attestation 按 ADR-008 绑定稳定文件身份、精确内容和发布阶段。一次 macOS/APFS 重启后，已完整发布且可核对的 canonical generation 出现持久 `st_dev` 与当前 `st_dev` 不同；source、manifest、SQLite 的 inode、size、SHA-256、resource/store identity、schema 和 publication phase 均保持一致。普通冷开正确地 fail closed，但资源没有安全入口重新证明当前平台文件身份，只能永久停在 unavailable。

不能简单忽略 `st_dev`：设备号仍是发现路径替换、跨设备绑定和混合身份的重要反例。也不能通过重建 generation 掩盖该问题，因为内容与 canonical authority 并未改变。本决策为 ADR-008 所保留的“平台文件身份机制改变”建立一个窄、显式且可审计的 maintenance transition。

## 决策

1. 普通冷开和查询继续严格执行 ADR-008；任何 active attestation 身份不匹配都不得自动开放 canonical authority，也不得回落 legacy。
2. 只有已完成 `GENERATION_PUBLISHED`、不存在 pending terminal/temp/stage 或 recovery 歧义，且唯一不一致事实是平台 device number 整组漂移时，Core 才可将资源分类为 `CANONICAL_REATTESTATION_REQUIRED`。该分类不是 authority publication，只授权显式维护入口。
3. “整组 device-only 漂移”必须同时满足：持久 source/manifest/SQLite attestation 共享同一个旧 device，当前 no-follow 观察共享同一个新 device，二者不同；每个 artifact 的 inode、size 与 SHA-256 精确匹配；resource id、store id、generation、manifest/binding、schema 与 publication phase 全部闭合。
4. 用户显式选择“重新验证 canonical”后，Core 在该资源持久锁下重新执行完整证明，并等待既有 query lease 边界。成功只原子替换 durable journal/attestation 中的平台设备身份，然后重新打开同一个 store id 与同一个 generation；不得重建 SQLite、迁移 source、改写 manifest 或改变 TM 内容。
5. 该维护入口适用于任意完整发布的 active generation，不得把 generation 1+ 降级或重铸为 generation 0。
6. inode、size、bytes、digest、resource/store/generation、binding、phase 任一变化，持久 artifact 使用混合旧 device，当前 artifact 使用混合新 device，或存在 pending/ambiguous recovery fact 时，重新证明必须 fail closed 且零 mutation。
7. 失败与等待状态只影响该资源；健康 peer TM 继续按各自 authority 查询。成功后由现有 runtime replacement 原子刷新当前段，不创建第二份 lifecycle authority。
8. canonical re-attestation 与 Gate D/Fuzzy 设备资格正交：它不得运行、恢复或撤销 Gate D，不得从 canonical 状态推断 Context/Fuzzy。Core current-source 或 Gate C identity 发生变化时，ADR-013 compatibility 可以独立失效并要求另行显式重验 Fuzzy。

## 长期约束

- “稳定文件身份 + 精确内容 + 已完成阶段”仍是 canonical authority 不变量；本 ADR 只增加 device-only、用户显式、同 generation 的维护转换。
- Qt 只经 `EditorController` 请求操作并显示 allowlisted safe code；不得读取或重写 journal/attestation。
- 不自动清理、跟随或修复未知 alias、symlink、hardlink、stage residue 或 pending recovery artifact。
- 未来若用 volume UUID、file-id 或其他平台 identity 取代 POSIX device/inode，仍需新的 ADR 与跨重启、替换、混合身份反例。

## 后果与权衡

合法 APFS 重启后的 device-number 漂移不再永久封死完整 canonical TM；用户可以在不重建内容、不改变 generation、不影响 peer 资源和 Fuzzy 资格的情况下恢复查询。代价是 activation recovery 多一个严格 maintenance transaction，必须持续验证跨 generation、混合 identity、byte/inode drift、pending recovery 和资源局部性。

## 备选方案

- **普通打开时忽略 `st_dev`**：拒绝。它把修复窗口扩大到所有查询，并削弱路径替换与跨设备反例。
- **自动重写 attestation**：拒绝。身份变化必须可见、显式且在持久锁下重新证明。
- **重新迁移为新 generation**：拒绝。内容没有变化，重建会伪造 authority 变化并引入不必要的 publication 风险。
- **只允许 generation 0**：拒绝。合法更新后的 generation 同样可能跨重启，限制会造成降级或永久不可恢复。
- **改为 legacy exact-only**：拒绝。ADR-007 禁止已发布 canonical 静默回落 legacy。

## 取代关系

- **取代**：仅部分取代 ADR-008 对“平台文件身份机制改变必须另经 ADR”的未决处置；ADR-008 的稳定身份、精确内容、阶段、seal/publication 与 fail-closed 约束继续保留。
- **被取代于**：None
