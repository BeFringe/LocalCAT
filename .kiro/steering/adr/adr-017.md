# ADR-017：TM Candidate Storage Port 与 SQLite Candidate 数据面分离

- **状态**：已采纳
- **日期**：2026-08-21
- **决策 owner**：LocalCAT 项目 owner
- **关联 Spec**：`tm-store-module-extraction`；`tm-storage-retrieval-index`

## 背景

`tm_sqlite_store.py` 已同时承载 canonical TM store 入口、coordinator/generation/transaction authority、candidate DTO/validators，以及 recall/proof/projection SQL。`tm_candidate_index.py` 因此直接导入 `SQLiteTMStore`、`SQLiteTMQueryView` 和 store 私有 dense validator。该耦合让 candidate algorithm、SQLite 数据面与 Gate C/D implementation roots 形成过大的共同变更面。

Feature 5 已分别把 activation durable protocol、schema-upgrade data plane 和 snapshot artifact protocol 提取到独立模块，并证明行为保持型数据面提取可以不迁移 canonical authority。当前最小可审计的下一步是 candidate storage port：algorithm 只依赖中立行为合同，SQLite candidate SQL 由独立数据面拥有，store/query-view 仍持有 connection、transaction、generation 与公开入口。

项目 owner 已明确批准按“TM Store 治理 → TM Store 解耦”推进，并批准为最终 source roots 支付完整 Gate C/D 成本；该维护线可在 Multi-Document 附近独立实施，但不得成为 Multi-Document 的前置依赖。

## 决策

1. 新建叶合同模块 `tm_candidate_store_contracts.py`，作为 candidate DTO、版本/块常量、candidate error、纯 validators/builders 与读取 port 的唯一 authority。该模块不得导入 store、retrieval、Engine、Application 或 Qt。
2. `tm_candidate_index.py` 只消费 `CandidateRecallPort` / `CandidateProofPort` 及叶 DTO，不再导入或 exact-type 检查 `SQLiteTMStore` / `SQLiteTMQueryView`，也不导入 SQLite projection concrete implementation。
3. 新建 `tm_sqlite_candidate_projection.py`，作为 recall/proof/projection SQL 与 row-decoding 的唯一数据面 owner。它只消费 caller-owned connection、已验证的 immutable facts 和叶合同，不自行打开 canonical authority。
4. `SQLiteTMStore` 继续拥有公开 store/coordinator 入口、connection policy、BEGIN/COMMIT/ROLLBACK、schema/bootstrap、ledger/binding、generation/capability publication 与 stable error mapping；`SQLiteTMQueryView` 继续拥有 captured-generation lifetime/expiry。
5. 写入 candidate rows、proof summaries 与 canonical records 必须继续处于既有 store-owned transaction；projection 不得 commit、rollback、发布 generation/receipt/capability 或改变 source binding。
6. 为保持严格行为等价，现有 `SQLiteCandidate*`、`SQLiteStoreSchemaError` 等历史名称本轮可作为叶模块中的 canonical object 保留，并由 `tm_sqlite_store` re-export 同一对象；不得用 compatibility subclass 或复制 dataclass 建立第二 authority。
7. 既有 private fault patch target在首次提取中保留为 `tm_sqlite_store` 的 late-bound delegate，直到 closed production/tests/evidence scan 证明无消费者；wrapper不得保留SQL或平行validator。
8. candidate algorithm继续独占 budget、stage union、proof frontier、U1/U2/U3/U4、P1/P2/P3、scorer invocation、threshold/top-k completion；本 ADR 不授权改变 proof-query-v3、scorer、schema 或排序。
9. 新 leaf/projection/store/index roots 必须使旧 current-source evidence、Gate C roots 与 Gate D implementation fingerprint 失效。最终必须在同一 source tree 上真实运行 100,000 条 FTS5 与 fallback intended paths，并重新生成 fault/acceptance/release evidence；不得只重签旧摘要。

## 长期约束

- Candidate port 不得暴露 connection、transaction、coordinator、lease token、generation grant 或 publication authority。
- SQLite projection 不得导入 store、candidate algorithm、retrieval、Engine、Application、Qt、Parser、Multi-Document、Chunk 或 Sync。
- 兼容入口/wrapper 只能保护调用形状与 fault seam，不能保留第二份 SQL/validator。
- schema/bootstrap、completed-authority rehydration 与 `tm_contracts.py` 拆分需要独立维护规格和证据窗口。
- 本维护线不得阻塞 Multi-Document；但跨设备资源可移植性/同步不得绕过 canonical TM owner而复制 live SQLite、journal、sidecar或stage residue。

## 后果与权衡

Candidate proof algorithm 与 SQLite store 可以分别审计、测试和演化，新的 candidate data plane 也能成为清晰的 Gate C/D source root。代价是必须保留一段受控的 re-export/late-bound compatibility surface，并为看似“纯重构”的 source-root 变化支付完整 current-source、Gate C 与 100k Gate D 成本。

历史 `SQLiteCandidate*` 名称暂不改名，牺牲部分命名整洁来保持 exact class object、repr、import 和 fault seam；未来若要改名，应另做契约修订而非夹带在数据面提取中。

## 备选方案

- **继续由 `tm_sqlite_store.py` 同时拥有全部 candidate 责任**：拒绝。algorithm 与 store concrete 依赖持续扩大共同变更与 evidence 面。
- **按行数拆 coordinator/schema/recovery**：拒绝。文件体量不是 authority 可迁移的证据，且会把多个状态机与 Gate 成本叠在一起。
- **让 projection 自行连接/提交**：拒绝。会把 canonical transaction 和 generation authority迁出 store，破坏 append/streamed 原子性。
- **只把类复制到新模块并保留旧定义**：拒绝。会形成双 object authority，exact-type 与 patch surface漂移。
- **保留 algorithm → concrete store，只移动 SQL**：拒绝。没有闭合主要依赖方向问题。
- **复用旧 Gate C/D bundle**：拒绝。实现 roots 已改变，旧资格不再证明当前代码。
