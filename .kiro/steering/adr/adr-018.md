# ADR-018：ProjectPackage 作为多文档工作区持久权威

- **状态**：已采纳
- **日期**：2026-08-22
- **决策 owner**：LocalCAT 项目 owner
- **关联 Spec**：`multi-document-project-workspace`；相邻 `language-resource-portability`、`collaborative-job-chunks`、`cross-device-sync-plugin`

## 背景

LocalCAT 当前的 `EditorProject` 把一个绝对路径、一个项目和一条扁平segment序列视为同一对象。Parser rebaseline已经把单输入格式读取、verified terminal和codec writer capability收回Parser/Codec边界，但它明确不拥有多文档Project/Document聚合、target工作区持久化、source reconciliation或跨文件保存。

多文档线必须同时解决三类不能混为一谈的事实：

- Project/Document/Segment的可移植稳定身份、显示顺序、target和确认状态；
- single file、directory或workbook等外部origin的source变化与可选writer；
- 后续手工传递和跨设备同步需要的不可变项目快照。

若直接把folder/workbook设为多文档唯一authority，reader-only TXT/PO/POT无法可靠保存target，目录partial write也会被误称为项目原子保存。若把同步provider或通用“Package”抽象设为authority，则项目身份、TM/术语资源和远端传输会共享错误的schema与merge语义。

项目owner已决定：Multi-Document Cluster 2完成手工ProjectPackage闭环，第一种真实多文档substrate是ProjectPackage；folder、multi-sheet XLSX与RPY后置。TM/术语资源以后建立独立ResourcePackage，只借鉴已验证的低层原语，不继承ProjectPackage authority。

这些已明确决定的跨规格 authority 与推进顺序使本 ADR 可以先于详细 R/D/T 采纳；它不批准尚在 Cluster 0 人工门中的字段、limits、物理 carrier 或 runtime 实现。`multi-document-project-workspace/spec.json` 在完整 R/D/T 获批前仍保持 `approved=false` / `ready_for_implementation=false`。

## 决策

1. **多文档持久权威**：版本化ProjectPackage是LocalCAT多文档workspace的canonical persistence，拥有project/document/segment identity、document order、source fingerprint、target、confirmation、detached状态、opaque member引用和保存baseline。
2. **Origin边界**：`single_file`、`directory`、`workbook`描述外部source origin与显式write-back范围，不是与ProjectPackage并列的workspace authority。absolute origin binding只在设备本地存在，不进入可移植package；换设备后必须显式重绑。
3. **Parser/Codec边界**：Parser/Codec继续独占单输入grammar、source snapshot、format metadata与live writer capability。Workspace只消费Application映射后的中立Document facts；ProjectPackage中持久的codec identity/capability不能自行授权source write-back。
4. **Reader-only持久化**：Reader不暗示Writer。TXT、PO、POT或其他reader-only source的target/confirmed由ProjectPackage持久；“项目包已保存”不等于“源文件已写回”。新增PO/POT canonical或round-trip writer必须由独立格式规格批准。
5. **身份**：项目内规范segment identity为`(document_id, local_segment_id)`。display name、sheet name、列表位置、Document order与source/target正文不得参与重铸identity。Document ID优先来自manifest；无manifest的获批adapter只能从规范化relative source_ref产生一次稳定ID并立即由ProjectPackage持久。
6. **Reconciliation**：source更新只按稳定Document/local segment ID和版本化source fingerprint比较。`source_changed`保留workspace target并撤销confirmed；`removed`、`ambiguous`、`unresolved`必须保留旧overlay/恢复引用并要求显式处置，不得按index或正文相似度猜测。
7. **真实原子性**：single-file和后续workbook profile只能在完整stage/validation后以同目录temp执行单文件原子替换。后续directory profile是多个物理文件，不能承诺跨文件原子性；它必须先完整stage/validate，再以durable journal逐项commit，失败逐Document报告`saved`、`rolled_back`、`unchanged`、`failed`并支持cold recovery。本ADR冻结红线，不批准当前directory/workbook产品入口。
8. **ProjectPackage闭环**：ProjectPackage必须冻结logical manifest/document/private-member schema，并在C2C人工门批准一个满足同一identity/digest/stale/LKG语义的physical carrier后，提供export、cold validate、body-safe preview、stale-bound import/apply与durable receipt。C0不指定ZIP或directory carrier；物理形态不参与项目身份。import/apply默认只安装ProjectPackage，不自动mutation任何origin。
9. **首包创建入口**：首批多文档 workspace 由用户在一个受验证 portable root 下显式选择 JSON/TXT/PO/POT 文件产生；每个文件都必须经现有 Parser 单输入 verified terminal 后才可聚合。该 `directory/explicit-selected-files-v1` profile 不递归扫描、不自动吸收未选择文件、不解释 workbook/sheet，也不授予 reader-only writer。
10. **Opaque member**：格式专属sidecar/token统一以可选`codec_private_member`保存。Core/workspace/UI/chunk/sync只能验证identity、version、digest、byte count并bit-preserving搬运；只有exact matching live codec可读取payload，且不得由Core局部merge或解释。
11. **同步边界**：未来sync provider只传输已验证的immutable ProjectPackage bytes/metadata，并调用同一validate/preview/apply事务；provider不解析manifest、不铸造项目identity、不自动解决翻译语义冲突，也不成为远端project authority。
12. **与ResourcePackage分离**：ProjectPackage与ResourcePackage是两个独立semantic authority。前者拥有项目结构和workspace状态；后者只拥有TM/术语profile、记录digest/count和资源receipt。可以复用atomic write、digest、bounded preview、receipt等低层实现原语，但不得共享manifest schema、ID、base class、merge规则或共同“package authority”。
13. **推进顺序**：Cluster 0只做规格治理；Cluster 1冻结identity/origin/single JSON adapter；Cluster 2A完成aggregation/reconciliation，2B完成save/recovery，2C完成ProjectPackage logical+physical闭环。Chunk只能在2A/2B/2C后开始；ResourcePackage R/D/T在2C后单独起草；Sync只消费已批准ProjectPackage/ResourcePackage；RPY产品排期在Sync后。

## 长期约束

- 当前single JSON继续是受支持的legacy canonical路径；用户未显式export/import package时不得强制迁移、改ID或改变公开save行为。
- 第一种 durable/reopenable canonical 多文档 persistence/import substrate 必须是 ProjectPackage；显式文件列表只产生 creation/staging candidate。folder scan、multi-sheet workbook和RPY folder不得借本ADR抢跑grammar或UI。
- ProjectPackage不得包含absolute origin path、live file handle、credential、provider state、device key、Gate D/Fuzzy qualification、live SQLite/sidecar/journal/stage residue。
- package preview、receipt、public error与log必须body-safe，不包含source/target/speaker/private payload或底层OS exception string。
- preview/apply必须绑定exact source artifact、destination baseline、project session/revision与single-use capability；任一变化零mutation fail closed。
- sync、chunk或resource consumer不得解释`codec_private_member`，也不得把opaque payload提升为第二项目authority。
- `current_chunk`只有协作规格批准稳定membership后才能加入search contract/UI；本ADR只冻结`current_document`与`entire_project`。
- TMX保持`language_resource`互操作格式；CONTEXT UI、TMX context/provenance/export和TMX project editor均不属于本ADR。
- 改变ProjectPackage schema/profile、identity、path normalization、limits、receipt或save/recovery协议必须走新的versioned contract与治理审查；不得静默兼容读取后回写成另一语义。

## 后果与权衡

ProjectPackage让LocalCAT在没有folder/workbook writer的情况下也能可靠保存多文档target，并为手工交接和后续sync提供同一不可变传输对象。稳定identity先于Chunk，使协作split/merge只能引用既有segment而不能重新定义Document。显式origin write-back又保留了未来格式codec安全回填的空间。

代价是多文档项目会区分“保存LocalCAT工作区”和“写回source origin”，UI与receipt必须诚实展示两种结果；未来directory profile还需要journal、backup和cold recovery，而不能用一个布尔成功值。ProjectPackage与ResourcePackage保持两套语义schema，也牺牲了一个看似通用的package抽象，但避免项目身份与语言资源authority互相污染。

## 备选方案

- **先实现folder/multi-sheet再补manifest**：拒绝。首个真实多文档身份会被路径、sheet名和枚举顺序锁死，且reader-only target无可靠持久位置。
- **把directory声明为原子项目保存**：拒绝。多个文件无法由一次`os.replace`原子提交；故障会产生无法解释的partial state。
- **每个workbook sheet分别写回**：拒绝。workbook是一个物理文件，只有完整生成、验证和单次替换才可声明成功。
- **让package内capability授权writer**：拒绝。包是非可信可移植输入；writer必须由当前设备的live codec registry重新授权并验证opaque token绑定。
- **reader-only格式保存target时直接覆盖成LocalCAT JSON**：拒绝。会把source writer与另存为LocalCAT工作区混为一谈，并可能丢失origin语义。
- **建立共同ProjectPackage/ResourcePackage基类和manifest**：拒绝。两者identity、记录、merge、receipt与owner不同；共享低层原语不等于共享semantic authority。
- **Sync直接复制workspace目录或live SQLite**：拒绝。会传播半写入状态、设备资格和本地store authority；sync只能搬运批准的immutable packages。
- **把Document当作Chunk**：拒绝。章节是内容结构，Chunk可跨Document拆分/合并且必须独立拥有membership与permission。
