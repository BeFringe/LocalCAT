# ADR-019：ProjectPackage v1 采用确定性单文件 ZIP carrier

- **状态**：已采纳
- **日期**：2026-08-22
- **决策 owner**：LocalCAT 项目 owner
- **关联 Spec**：`multi-document-project-workspace`；接续 ADR-018；相邻 `cross-device-sync-plugin`、`language-resource-portability`

## 背景

ADR-018 已冻结 ProjectPackage 对多文档 workspace 的逻辑持久权威，但明确不批准物理 carrier。C2C 实施前必须在真实双 Document fixture 上比较物理候选，并由项目 owner 人工选定唯一 production profile。

评估了两个能保持 ADR-018 identity/digest/stale/LKG 语义的候选：

- 单文件 deterministic ZIP；
- immutable generation directory + 原子 `CURRENT` regular-file pointer。

普通 in-place 目录不是合格候选，因为它无法用一个 publication point 承诺多 member 一致可见。

## 决策

1. **唯一 v1 carrier**：ProjectPackage v1 的唯一 production 物理 profile 为 `localcat-project-package-zip-v1`，它是一个确定性、不压缩、不可变的单文件 ZIP artifact。扩展名只用于 UI routing，不参与 profile 识别、project identity 或 content digest。
2. **classic stored-only envelope**：仅接受 classic single-disk ZIP 与 `ZIP_STORED`；拒绝 ZIP64、compression、encryption、data descriptor、multi-disk、unknown flag/method、entry/archive comment 和任何 extra field。v1 的 512 MiB artifact、8,192 members 与 256 MiB/member 上限不需要 ZIP64。
3. **canonical metadata**：固定 DOS timestamp 为 `1980-01-01 00:00:00`，固定 creator/extract version、UTF-8/general-purpose flags、Unix regular-file `0644`、internal/external attributes。不产生 directory entries、symlink、hardlink、device 或 executable member。
4. **physical member 闭集**：physical name 只允许 ASCII 布局 `manifest.json`、`documents/<document_id>.json`、`sources/<document_id>/<sha256>.bin` 和 `codec-private/<document_id>/<sha256>.bin`。顺序固定为 `manifest → documents → sources → codec-private`，后三组各自按 ASCII bytes lexical order。actual member set 必须与 manifest exact equality；物理顺序不授予项目身份。Unicode `source_ref` 只留在经验证的 canonical JSON 中，不映射为 ZIP member path。
5. **raw preflight 先于语义读取**：validator 必须先完整扫描 raw local headers、central directory 和唯一 EOCD，拒绝 SFX/prefix、trailing byte/拼接 archive、gap、overlap、duplicate、NFC/casefold collision、path escape 以及 local/central name、flag、size、CRC 不一致。offset 0 必须是首个 local header，EOCD 必须精确结束于 EOF。不得以 `zipfile.is_zipfile()`、`testzip()`、按名 dict 或 `read(name)` 代替这个闭集扫描。
6. **bounded streamed validation**：从 retained no-follow single-link regular-file handle 读取 artifact，包成员永不 extract 到文件系统。对每个 member 用固定小 buffer 完整消费，用 non-bool checked addition 复验 actual byte count/total，触发 CRC 校验并重算 SHA-256；CRC 不替代 manifest cryptographic digest。
7. **两种 digest 分工**：`artifact_digest` 是 exact ZIP bytes 的 SHA-256，用于搬运、stale 和 receipt；`workspace_content_digest` 是 carrier-independent 逻辑 workspace digest，用于内容身份和未来显式迁移。
8. **发布与 LKG**：导出和安装复用 C2B 的 `stage → cold validate → live revalidate → arm durable journal/LKG → same-parent atomic replace → parent durability → cold readback → finalize → second readback/cleanup proof`。首次发布的 LKG 为 `None`；覆盖时必须保留 exact 旧 artifact 作为 Last Known Good。无法证明同卷原子替换、parent/root durability 或 Windows reparse/final FileId 安全性时 fail closed，不用 copy-over/in-place fallback。
9. **未选 carrier**：`versioned-directory + atomic CURRENT` 与裸目录均不是 v1 production reader/writer，不保留并行 runtime。它们可在未来新 profile 治理中重新评估，不得被 v1 宽松读取。
10. **迁移**：v1 exact decoder 长期保留。未知 physical/schema profile 返回 body-safe unsupported failure。未来 v2 必须走 `v1 cold validate → logical workspace → 全新 v2 candidate → old/new artifact+content digest receipt`，旧 v1 不被原地覆盖，不得宽松读后静默按新语义写回。
11. **同步适配**：未来 S3/WebDAV provider 可以把 exact validated ZIP bytes、artifact digest、byte count 和版本化 receipt 作为同一 immutable transport object。provider 只负责远程 listing/conditional transfer/conflict/credential，不解析 ZIP/manifest、不铸造 project identity、不替代本地 validate/preview/apply。S3 与 WebDAV 的 ETag/version/conditional-write 语义由后续 sync Spec 分别冻结，本 ADR 不宣称远程多写者原子性。
12. **分权**：本 carrier profile 只适用 ProjectPackage。ResourcePackage 可以在其独立 R/D/T 中复用经验证的 deterministic archive/atomic write/digest 低层原语，但不因此继承 ProjectPackage manifest、ID、receipt、merge 或共同 package authority。

## 长期约束

- Python `zipfile` 可作为 raw preflight 后的 bounded STORED stream 实现组件，不是物理格式验证权威；不得调用 `extract()`/`extractall()`。
- 任何开启 deflate、ZIP64、新 member layout、新 comment/extra 或放宽 envelope 的改动，都需要新 physical profile 与独立迁移决策。
- transient candidate、LKG、journal、backup 和 cleanup residue 是本地 operation state，不得进入 terminal package 或 provider payload，也不得按 glob 猜测删除。
- sync 必须传输完整的 exact artifact；截断、digest 不符、receipt 不符或条件写冲突时不得 apply。
- 物理 carrier 不属于 Parser/Codec registry，Qt、Chunk、Sync 和 TM/Term resource layer 不得直接读取 ZIP member。

## 后果与权衡

单文件 artifact 有唯一 bytes digest，用户可手工搬运，未来 S3/WebDAV provider 只需处理一个不可变对象。STORED-only 避免压缩 bomb 与跨 zlib 版本输出漂移，大 opaque member 仍可分块验证。

代价是每次保存都要重写整个包，ZIP 头部必须自行做严格 preflight，且 v1 不能通过压缩降低体积。在 512 MiB 上限下这是明确且有界的产品取舍，不由实现层静默优化。

## 备选方案

- **immutable generations + atomic `CURRENT` regular-file pointer**：拒绝作为 v1。它在本机可以保留天然 LKG，但手工复制与 provider listing 可见 pointer/generation 不一致，需要多对象 snapshot、递归 no-follow/fsync、orphan GC 和更大的 TOCTOU 状态机。
- **裸目录 in-place**：拒绝。没有单一 publication point，会产生 partial package。
- **TAR/ustar**：拒绝。duplicate/link/device/PAX/padding/trailing 语义与无 CRC 带来更大闭集工作，Windows 产品体验也较差。
- **SQLite artifact**：拒绝。它引入数据库/journal authority，且不提供所需的 canonical bytes 稳定性。
- **自定义 framing**：拒绝作为 v1。它需自研长期 parser/migration，但不改善整包替换与大 member 重写的核心取舍。
