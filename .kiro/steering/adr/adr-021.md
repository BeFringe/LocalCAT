# ADR-021：Windows 设备本地私有证明与跨重启重新证明表示

- **状态**：已采纳（security profile V1由ADR-023窄范围修订，其余条款继续有效）
- **实施授权**：本ADR不单独授权实现；实现由已批准的`windows-platform-enablement` R/D/T及其task依赖图控制
- **日期**：2026-08-25
- **批准日期**：2026-08-26
- **决策 owner**：LocalCAT 项目 owner
- **关联 Spec**：`windows-platform-enablement@c3a1080d5e8dbf13c3dde943bd48c033e2105a87`（working label W2）；相邻 `tm-storage-retrieval-index`、`feature5-ui-integration`

## 背景

ADR-013 用当前用户 profile 下的 POSIX owner/mode/nlink、device/inode、原子文件替换和 directory fsync 表达 Gate D 设备本地资格；ADR-016 又为完整发布的 canonical authority 增加了严格、显式、device-only 漂移重新证明。Windows 的 `chmod` 不能证明相同权限，owner 与 access 由 SID/security descriptor/DACL 表达，default DACL 也不能默认为私有。同时 Windows FileId 只适合 live-handle 比较，不能直接保存为永久跨重启身份。

把 POSIX mode/dev/inode 字段原样复制、只检查当前账户名、接受任意“看起来私有”的 ACL，或仅凭历史 FileId 恢复 capability，都会改变持久格式、授权与 recovery boundary。本 ADR 只批准 `WindowsPrivateProof` 子记录及其物理 ACL 表示；Gate D envelope 仍归 ADR-013，canonical envelope 仍归 ADR-016 与 TM owner。采纳本决策不批准 TM 或 UI 实现。

## 决策

本 ADR 作出以下决策：

1. **依赖 W1 authority**：Windows private proof 只能建立在 ADR-020 采纳后的 rooted/live-handle、identity、error 与 publish contracts 上。ADR-020 自己拥有 protocol-control lock file 的完整 ACL profile，W2 不承接该 lock file，因而不存在 W1→W2 依赖。无法 mint W1 capability 时，private attestation 和 cross-restart recovery 同样 fail closed。
2. **主体身份**：首版私有主体是进程 primary token 的 `TokenUser` SID，以 canonical SID bytes 比较，不使用显示名、账户名或路径名。标准与 UAC elevated token 必须解析为同一用户 SID；service、AppContainer、impersonation token 和无法分类的 token 首版 capability unavailable。
3. **exact `WindowsPrivateAclV1`**：private directory、device key、attestation 与它们的 candidate 都必须逐对象显式应用同一个 security descriptor；不依赖 parent/default DACL，也不通过 inheritance 派生。owner精确等于当前primary token的canonical `TokenUser` SID；DACL revision固定为`ACL_REVISION`，authority-relevant control bits必须`SE_DACL_PRESENT|SE_DACL_PROTECTED`且清除`SE_DACL_DEFAULTED|SE_DACL_AUTO_INHERITED|SE_DACL_AUTO_INHERIT_REQ`，representation-only `SE_SELF_RELATIVE`归一化后不参与比较。DACL按canonical order精确包含3个`ACCESS_ALLOWED_ACE_TYPE`且每个`AceFlags == 0`：`TokenUser` canonical SID bytes、`CreateWellKnownSid(WinLocalSystemSid)`所得`S-1-5-18`、`CreateWellKnownSid(WinBuiltinAdministratorsSid)`所得`S-1-5-32-544`；三者mask均为`FILE_ALL_ACCESS`。不得以localized name/account lookup解析well-known principal；null/defaulted DACL、任何其他control/ACE flag、deny/object/callback/inherited/unknown ACE、额外principal或不同mask都必须拒绝。W1的persistent protocol-control lock file不属于这个对象集合。
4. **handle-bound descriptor reproof**：验证必须对已 rooted、reparse-free 的 retained handle 调用 security/identity API，精确检查 owner SID、DACL protected/no-inheritance、ACE type/order/mask、kind、link count、live VolumeSerial/FileId 与支持 volume。pathname ACL 查询、`os.chmod`、当前用户可读写或“等价安全”的 ACL 不能替代 exact profile。
5. **规范化 `AccessCheck`**：授权探针从当前 process primary token 复制 `SecurityImpersonation` 级 impersonation token；requested access 固定为 `GENERIC_ALL`，分别使用文件与目录对象的固定 `GENERIC_MAPPING` 执行 `MapGenericMask`，其结果必须精确为 `FILE_ALL_ACCESS`，再对 retained handle 读取到的 descriptor 执行 `AccessCheck`。descriptor 精确匹配、全部 requested rights 获准且无 residual generic bits 才能通过；任一 API/fact 不可得即 fail closed。实现不得用调用成功、管理员身份或当前进程已持有 handle 反推权限安全。
6. **token 与 mandatory-integrity 范围**：证据矩阵必须分别覆盖 standard/elevated token，以及本地、domain、AzureAD `TokenUser` SID；两种受支持 token 都必须获得上述 `FILE_ALL_ACCESS`，同 SID 的 low-integrity/restricted token 必须不能获得 write/delete。service、AppContainer、impersonation-only 或无法分类的 token 首版 unavailable。SACL/audit ACE 不是 discretionary authorization 输入，也不能因读取不到 audit policy 而把已知合格 DACL 判成授权；mandatory-integrity 的可观察授权结果仍由正/负 `AccessCheck` 矩阵强制，未知或不满足矩阵时 fail closed。
7. **仅拥有 `WindowsPrivateProof` 子记录**：W2 只定义 versioned `WindowsPrivateProof` 的 schema、canonical encoding 与验证器；它绑定 object role、`WindowsPrivateAclV1` profile/version、canonical owner SID、authority-relevant security-descriptor digest、owner 提供的 opaque context digest、device-key identity 与 device-secret proof。它不定义或复制 owner envelope 的 content、phase、generation、compatibility/provenance 或 canonical authority 字段，也不拥有这些 envelope 的 publish/recovery state machine。live FileId 只进入当次 live-handle 证明或诊断，不成为持久 authority。
8. **无循环的 device-secret 组合**：设备密钥只位于同一 Windows private storage authority 下，由 Core owner 创建并按 `WindowsPrivateAclV1` 验证；密钥、attestation 和临时 candidate 使用相同 private-proof contract。各 business owner 先按自身获批 schema 生成不含 `WindowsPrivateProof` 的 canonical private-context bytes，W2 只保存其 SHA-256 为 `owner_context_sha256`。`device_secret_mac` 固定为对 domain tag、W2 schema、object role、ACL profile、owner SID digest、authority-descriptor digest、`owner_context_sha256` 与 device-key id 的 canonical unsigned projection 执行 HMAC-SHA256；MAC 字段自身不进入输入。owner envelope 再嵌入完整 proof，并独立验证自身 canonicalization/phase/generation/compatibility。该组合没有 self-MAC，也不让 W2 解释或拥有 business envelope。项目包、资源包、sync payload、UI cache 或安装目录不得携带/重铸密钥。
9. **跨重启重新证明**：恢复必须由 owning envelope verifier 重新 bind 当前 root/object，复核 current owner/DACL/link/reparse/live identity、exact bytes/digest、`WindowsPrivateProof`、device-secret MAC 及 owner-specific phase/generation/compatibility/semantic closure，随后才由 Core 私有 factory 重铸 runtime capability。任一不一致、混合 identity、pending/ambiguous recovery 或未知 residue 均零 mutation fail closed。
10. **业务边界保持**：Gate D envelope、compatibility/provenance 与真实运行仍归 ADR-013；canonical envelope、显式 maintenance transition 与 same-generation 限制仍归 ADR-016 和 TM owner。Windows representation 不能从 valid ACL 推断 Fuzzy/canonical capability，不能自行定义 generic compatibility receipt，也不能自动改写业务 journal/attestation。
11. **支持矩阵**：批准与实现证据必须覆盖 standard/elevated、本地/domain/AzureAD 用户 SID、完整性级别、显式/继承 ACE、未知 principal、owner/DACL tamper、hardlink/reparse、delete/recreate/FileId reuse、跨重启与 device-secret mismatch。未覆盖主体、integrity policy 或 volume fail closed，不得以 skip 计为支持。
12. **公开失败与 UI**：底层 SID、ACL、path、security descriptor 与 secret facts 不进入 UI/public error。平台返回稳定 private-storage-unproven/capability-unavailable facts；Core/Controller 只显示既有 body-safe、resource-local 投影。

## 长期约束

- Windows ACL/SID 表示在 Windows 物理范围取代既有 POSIX identity predicates，但不把两个平台的物理字段强行统一，也不允许业务模块直接判断 mode/uid/SID/DACL。
- live FileId、账户名、`chmod(0600)`、调用方“private=true”、可读写探针或普通 HMAC 文件均不能独立重授权。
- 重新证明只恢复同一已发布业务 authority；不得借 private proof 重建 SQLite、改变 generation、迁移 source、开放 Fuzzy 或把 legacy 提升为 canonical。
- 设备密钥和完整 attestation 都是本地 operation state，不能进入 portable package、provider payload、diagnostic log 或 Qt state。
- 改变 `WindowsPrivateAclV1` 的 principal/right、token/integrity scope、`WindowsPrivateProof` schema/MAC composition、跨重启 success boundary 或支持的 filesystem/token 类型，必须重新治理；generic envelope 字段的改变必须回到其业务 owner。

## 后果与权衡

这项表示让 Windows 能在不伪装 POSIX mode/inode 的前提下恢复设备本地资格和已发布 authority，并保留 ADR-013/016 的显式、fail-closed 语义。代价是 ACL 验证、token 分类、device-secret 生命周期和跨重启矩阵更复杂；某些服务、沙箱或权限异常环境会被有意拒绝，而不是降级为较弱证明。

## 备选方案

- **用 `chmod(0o600/0o700)` 或 writable check 近似**：拒绝。Windows chmod 不表达所需 owner/DACL contract。
- **信任 default/inherited DACL**：拒绝。不同 token、parent 与企业策略下不能推出精确私有边界。
- **按账户显示名比较**：拒绝。rename、domain/AzureAD 与本地同名账户会破坏身份。
- **保存 VolumeSerial/FileId 作为永久身份**：拒绝。删除后可能复用，跨重启还必须绑定 exact content、phase、private proof 与 device secret。
- **attestation 不合法时自动重建或自动重跑 Gate D**：拒绝。会越过 ADR-013/016 的显式 Core transition 和业务 authority。

## 取代关系

- **取代**：仅在 Windows 物理表示范围部分取代 ADR-013 决策 8 及 ADR-016 的 POSIX identity predicates，以 `WindowsPrivateAclV1`、live-handle identity 与 `WindowsPrivateProof` 子记录替代 mode/uid/dev/inode 表示；ADR-013 的 Gate D envelope/compatibility authority，以及 ADR-016/TM owner 的 canonical envelope、generation、显式重验、same-generation 和 fail-closed 语义继续有效。
- **被取代于**：ADR-023以`WindowsPrivateSecurityV2`修订决策3～7中的V1 profile/proof绑定；原owner、DACL规则、业务envelope与失败边界继续有效
