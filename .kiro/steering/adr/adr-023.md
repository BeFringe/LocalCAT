# ADR-023：Windows pre-authority 证明时序细化与安全 profile 修订

- **状态**：已采纳（durability registry由ADR-025取代，其余条款继续有效）
- **实施授权**：本ADR不单独授权runtime、build或发布；实现由已批准的`windows-platform-enablement` R/D/T及其task依赖图控制
- **日期**：2026-08-26
- **批准日期**：2026-08-26
- **决策 owner**：LocalCAT 项目 owner
- **关联 Spec**：`windows-platform-enablement` Task 0.4a/0.5；ADR-020、ADR-021、ADR-022

## 背景

ADR-020～022 已确定 Windows rooted/lock/publish、private re-attestation 与 frozen bootstrap/build 的长期 owner、authority 和失败边界。Task 0.5 独立对抗性评审发现其中若干实现前仍需闭合的遗漏情形与 API 时序：`CREATE_NEW` 对已存在锁载体返回 `ERROR_FILE_EXISTS`，不能把所有 loser 都按 INIT sharing violation 处理；DACL-only profile不能实际证明Windows Mandatory Integrity Control，也不能同时保证elevated创建后standard可用和low-integrity不可写；既有retained-readback生命周期还缺少阻止preliminary success的类型化API表达；frozen runtime没有从bundle authority取得`DurabilityProfile` registry的闭合路径；PE static/delay-load闭包也不包含pre-authority代码内部的动态`LoadLibrary*` roots。

LOCK-first分流、`PendingPublication`、durability registry获取路径与动态native closure都细化既有owner/authority，不改变其归属；V1→V2则是窄范围纠正，因为先前DACL-only表示无法实现已写明的mandatory-integrity目标。这些都不新增证据审批门，但会长期约束多个Spec，故用本补充ADR保留发现原因、精确修订范围和可追踪血缘，而不是让原ADR看起来从一开始就已经包含这些后来发现的细节。

## 决策

1. **LOCK-first已有载体分流**：首次creator仍以`CREATE_NEW`+INIT share-none handle创建、写入、flush和readback。loser收到`ERROR_FILE_EXISTS`后先以普通LOCK profile执行`OPEN_EXISTING`；该open sharing violation才表示INIT creator/recoverer仍持handle并进入bounded retry。普通open成功后必须handle-bound复证root、entry、security profile、single-link和payload：完整expected payload直接进入普通flush/readback与`LockFileEx`；空或expected strict-prefix先关闭普通handle，再争抢INIT share-none handle并二次复证后确定性恢复；unknown/超长/非前缀或未识别状态fail closed。INIT完成后必须关闭并重新普通open，载体不得unlink/replace。
2. **显式Mandatory Integrity profile**：ADR-020 protocol-control lock与ADR-021 private对象都必须显式设置并handle-bound重验authority-relevant MIC projection：恰有一个`SYSTEM_MANDATORY_LABEL_ACE_TYPE`，`AceFlags == 0`，SID为medium integrity `S-1-16-8192`，mask为`SYSTEM_MANDATORY_LABEL_NO_WRITE_UP`。读取时对已有`READ_CONTROL` handle请求`LABEL_SECURITY_INFORMATION`，并与owner/DACL projection成套验证；不得改用需要`ACCESS_SYSTEM_SECURITY`的完整`SACL_SECURITY_INFORMATION`，也不得因无法取得完整audit SACL而扩大运行权限。audit ACE与mandatory-label ACE必须分开解析；audit policy不作为discretionary authority，但额外、未知、缺失或漂移mandatory-label ACE均fail closed。真实standard/elevated正向与low-integrity/restricted-token负向子进程矩阵验证OS行为，DACL-only `AccessCheck`不能代答MIC。
3. **security profile版本**：ADR-020的`ProtocolControlLockSecurityV1`由`ProtocolControlLockSecurityV2`接管；ADR-021的`WindowsPrivateAclV1`由`WindowsPrivateSecurityV2`接管。V2保留原exact owner/DACL/ACE规则并加入上述MIC projection；`WindowsPrivateProof.security_profile_id`与`authority_descriptor_sha256`必须绑定V2 canonical owner+DACL+MIC projection。Windows实现尚未落地，因此首版不提供V1兼容读取或自动迁移；遇到V1/unknown profile fail closed，未来迁移须另行治理。
4. **显式pending publication handshake**：ADR-020既有rename→candidate close→retained readback→owner durable commit→terminal reproof顺序由opaque、context-managed `PendingPublication`表达。`begin_publish`只能返回preliminary platform facts与retained destination authority，不能返回success或generic business receipt；owner在pending authority存活时完成自身readback、durable commit与business-state reproof，再调用platform terminal identity/digest reproof并关闭。任一步失败进入owner recovery-required分类。
5. **W1 durability registry authority**：W1 owner发布clean tracked、canonical、版本化`DurabilityProfileRegistryV1`（首版路径`packaging/windows/durability_profiles.json`）。每项包含profile id、host/volume/cache/power facts、portable forced-power-loss evidence manifest key与SHA-256；registry本身由rooted handle读取并content-address。source composition只接受显式rooted registry authority；W3 build manifest必须收集、摘要并随dist布置该artifact，frozen composition只接受bootstrap bundle authority提供的manifest-bound handle。registry/profile/evidence digest缺失、tamper、mismatch或CWD/checkout fallback均不得mint durability capability；大型power evidence本体不要求进入dist。
6. **完整pre-authority native closure**：W3 native bootloader除递归枚举PE static/delay-load closure外，还必须从owner manifest取得所有可能在`TrustedSourceAuthority`前执行的hook/stdlib/ctypes extension的动态`LoadLibrary*` native roots。所有非系统成员在首次可执行load前完成retained-handle rooted/reparse/live-identity/digest proof并固定依赖搜索；加载后只复核actual module与预证明handle，不能用post-load检查补救。未声明dynamic load、无法闭合的依赖、unexpected module或只约束顶层DLL的search flags均使spike/release fail closed。
7. **审批与证据边界**：本ADR只冻结上述表示与证明顺序，不新增ADR采纳evidence要求，也不改变现有power-cut、token、native tamper和packaged E2E作为实现/发布证据的归属。独立reviewer已确认R/D/T映射闭合；具体实现仍按`windows-platform-enablement` task依赖逐项进入。

## 长期约束

- 正常活跃LOCK handle不能被误判为INIT；完整payload路径不得争抢share-none恢复handle。
- MIC是security authority的一部分，不是audit policy，也不能依赖creator token的默认label；label projection通过`LABEL_SECURITY_INFORMATION`读取，不要求或假装持有完整SACL审计权限。
- durability registry是runtime mint的唯一发布配置source of truth；build manifest只布置和证明它，不替代W1 owner。
- pre-authority动态native roots必须显式声明；`DllMain`执行后的path/digest检查只能复核，不能建立先前信任。
- 平台pending publication不解释或持久化Project/TM/Resource/Chunk业务phase、generation、compatibility或receipt。

## 后果与权衡

本决策补齐已采纳Windows边界的实现前证明顺序，使其不会误分类并发、遗漏MIC或动态DLL，并能在无checkout EXE中取得耐久配置。代价是security descriptor与manifest schema增加、bootloader需要显式动态native roots、Windows首版拒绝旧/未知profile，并仍需custom bootloader可行性spike。

## 备选方案

- **把后来发现的细节全部回写进ADR-020～022，表现为初始决策的一部分**：拒绝。已采纳ADR可以更新状态、Steering同步结果、引用与不改变语义的勘误；但V1→V2修订及跨ADR长期时序补充应保留发现原因和演进血缘，不能静默改写既有决策语义。
- **`ERROR_FILE_EXISTS`后直接争抢INIT**：拒绝。正常LOCK handle会造成sharing violation并被误判为初始化未完成。
- **只检查DACL或依赖默认integrity label**：拒绝。不能同时保证elevated→standard可用与low-integrity不可写，也不能检测label降级。
- **从checkout/CWD读取DurabilityProfile**：拒绝。frozen release不自包含且形成第二authority。
- **只枚举PE imports或加载后核对DLL**：拒绝。动态load不在PE闭包内，`DllMain`已经执行。

## 取代关系

- **取代**：获采纳后，仅以`ProtocolControlLockSecurityV2`取代ADR-020决策5中的V1 security profile，并以`WindowsPrivateSecurityV2`取代ADR-021决策3～7中的`WindowsPrivateAclV1` profile/proof绑定；原owner、DACL规则、业务envelope与失败边界继续有效。
- **补充**：ADR-020决策6/9/10的LOCK-first既有载体分流、`PendingPublication` API与durability registry authority，以及ADR-022决策3/5/8/10的pre-authority动态native closure；这些细化不取代原authority、ownership、release profile或证据归属。
- **被取代于**：ADR-025取代决策5、决策7中的runtime durability registry与forced-power-loss blocking requirement及相关长期约束；token/native tamper与packaged E2E证据归属、LOCK-first、MIC/security profile、pending publication与native closure继续有效
