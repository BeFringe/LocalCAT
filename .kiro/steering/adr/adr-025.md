# ADR-025：Windows 发布耐久合同与硬断电资格分层

- **状态**：已采纳
- **实施授权**：本ADR不单独授权runtime、consumer或发行实现；实现由已批准且同步修订的`windows-platform-enablement` R/D/T及cross-Spec依赖图控制
- **日期**：2026-08-28
- **批准日期**：2026-08-28
- **决策 owner**：LocalCAT 项目 owner
- **关联 Spec**：`windows-platform-enablement`；ADR-008、ADR-013、ADR-016、ADR-018～023；WA-03～08

## 背景

ADR-020决策10/11把Windows发布成功绑定到release-owned `DurabilityProfile`：runtime必须精确匹配Windows build、storage bus/media、write-cache、power-protection等硬件事实，并绑定同一profile的真实forced-power-loss evidence。ADR-023又把该registry加入source rooted authority与frozen bundle closure。该设计试图为突然断电后的物理持久性建立设备级资格，但它超过LocalCAT既有POSIX `fsync`/directory-fsync合同和本次Windows迁移的产品目标。

普通Windows 11用户无法提供与其storage controller/cache/power-protection完全匹配的实验室证据；即使Qt、rooted authority、锁、`FlushFileBuffers`、原子命名、readback和业务recovery均正常，runtime仍会在保存前返回`DURABILITY_UNAVAILABLE`。这使“用户管理Python的source可用”和“可运行EXE”名义上分线，实际上同时被硬件认证阻断。真实突然断电资格可以是有价值的独立声明，但不应成为普通项目保存、TM恢复或打包的隐含前置。

## 决策

1. **Windows documented publish baseline**：首版Windows发布采用`WindowsDocumentedPublishV1`语义：Windows 11 x64、本地固定NTFS、rooted/reparse/live-identity与owner lease成立；candidate以获批access/share/`WRITE_THROUGH` profile创建，写入后`FlushFileBuffers`，执行handle-bound原子命名，关闭candidate，reopen retained destination并完成exact bytes/digest readback、owner state-machine commit与terminal reproof。该语义与现有POSIX file/directory fsync合同同级。
2. **支持与失败边界**：publication arm前若所需Windows API、local fixed NTFS、安全descriptor/reparse/FileId、flush/write-through或handle-bound naming能力不可用，返回`DURABILITY_UNAVAILABLE`并保持零命名mutation。arm后若命名结果、destination reopen/readback、owner durable commit或terminal reproof失败/不确定，返回`RECOVERY_REQUIRED`并交由owner按完整old/new/recovery-only分类。Windows build/patch、storage bus/controller、cache枚举值、设备自报power protection和forced-power-loss evidence不再是普通publish capability的mint条件。
3. **恢复证据**：source与packaged发行的blocking矩阵覆盖instruction-boundary fault、process termination、双进程竞争、目标占用、完整old/new/recovery-only、应用重启及正常OS reboot后的重开/重新证明。它们证明LocalCAT协议与Windows已确认的flush/naming结果，不冒充突然断电硬件认证。
4. **硬断电声明分离**：真实forced-power-off、volatile-cache与硬件power-protection资格移出当前Windows source milestone、EXE构建、frozen authority和最终产品GO。当前发行不宣称能在存储设备违反已确认flush语义或未受保护的突然掉电中保证新数据存活。未来若产品需要“经认证的突然断电耐久性”声明，必须由独立Spec/ADR定义硬件profile、实验室evidence、支持列表和用户可见承诺；该资格不得静默改变普通publish authority。
5. **移除runtime registry**：`DurabilityProfileRegistryV1`和`packaging/windows/durability_profiles.json`不再是source runtime、W3 manifest、frozen dist或release validator的必要输入。不存在从CWD/checkout读取它的fallback，因为当前产品根本不消费该registry。大型power evidence同样不进入发行闭包。该收窄只改变ADR-023后来加入的durability registry输入；ADR-022的native entry、Boot TCB、DLL closure、`TrustedSourceAuthority`、真实`.py`/fixture authority、clean build provenance及packaged业务E2E全部继续有效，WA-07/08只删除相同registry依赖。
6. **业务owner不变**：platform仍只返回`PendingPublication`与低层facts；Project、Resource、TMX、Chunk与TM owner继续持有journal/LKG、generation、receipt、durable commit和recovery分类。分层不允许preliminary facts充当success、不降低retained-readback/terminal-reproof或把ambiguous结果当作已发布。
7. **跨平台对称**：macOS/Linux既有openat/no-follow/fsync/directory-fsync与业务恢复语义不增加硬件profile门；Windows使用文档化API获得同层合同。任何平台都不因本ADR自动获得未经单独验证的硬件掉电认证。

## 长期约束

- 普通publish成功表示应用协议与OS文档化flush/naming/recovery合同闭合，不表示对任意控制器、固件或未受保护电源故障作绝对保证。
- process crash、应用重启、正常OS reboot与forced power loss必须使用不同证据名称和结论，不能互相代答。
- `DURABILITY_UNAVAILABLE`继续保护真实API/volume/flush/naming能力缺失；不得用已取消的hardware registry重新扩大普通runtime门。
- 未来硬断电资格是附加产品声明，不反向成为source、普通EXE或业务owner authority的必要条件，除非新ADR明确改变产品范围并获人工批准。

## 后果与权衡

Windows source与EXE可以在普通受支持NTFS主机上完成保存、重开、TM激活/恢复、TMX与FTS5，而无需storage实验室或per-device allowlist；这恢复了与现有macOS/Linux发布合同的实际对称。代价是当前版本明确不提供经实验室认证的突然断电存活声明。若未来需要该声明，必须单独承担硬件矩阵、持续qualification和用户可见支持范围的维护成本。

## 备选方案

- **保留runtime硬件profile，只把实验移到frozen后期**：拒绝。它仍会阻断普通source和EXE在绝大多数用户设备上的保存能力，只是延后暴露问题。
- **完全取消flush/readback/recovery**：拒绝。Windows仍必须实现与POSIX同级的原子发布和崩溃恢复；本ADR只分离超出产品目标的硬件认证。
- **为首台开发机固定一个storage profile**：拒绝。它会把单机实验误当成Windows产品支持，并随系统/固件更新漂移。

## 取代关系

- **取代**：ADR-020决策10、11及决策14中`DurabilityProfile`/硬断电升级门；ADR-020其余rooted、lock、publish lifecycle、POSIX parity和fail-closed边界继续有效。
- **取代**：ADR-023决策5、决策7中runtime durability registry与forced-power-loss blocking requirement、长期约束中的runtime durability registry，以及相应补充关系；ADR-023的token/native tamper与packaged E2E证据归属、LOCK-first、MIC/security profile、pending publication与native closure继续有效。
- **保持**：ADR-008/013/016/018/019的业务durable commit、journal/LKG、canonical authority与recovery ownership不变；ADR-022除上述registry输入外的frozen发行合同不变。
