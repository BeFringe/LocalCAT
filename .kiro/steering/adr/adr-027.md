# ADR-027：Windows 导出输出锁的安全闲置回收

- **状态**：已采纳
- **实施授权**：只授权同步修订后的平台、Resource 与 TMX owning task；不改变 Qt 的文件权威边界
- **日期**：2026-09-05
- **批准日期**：2026-09-05
- **Owner Spec**：`windows-platform-enablement`（锁回收能力）；`language-resource-portability` 与 `tmx-context-interchange`（各自导出终态及回收调用）
- **关联 Spec**：`windows-platform-enablement`、`language-resource-portability`、`tmx-context-interchange`；ADR-020、ADR-023

## 背景

Windows 适配移交前，Mac 已完成并修复 TMX 上下文互操作；该基线的 Resource/TMX 导出不会在输出目录留下 `.resource-artifact-*.lock`、`.localcat-tmx-*.lock`。Windows 平台迁移引入目标族输出锁，并把 ADR-020 的永久载体规则应用到这两种导出，导致正常完成后仍留下用户未请求的文件。这是迁移新增行为，不能解释成既有 Mac 合同。

直接在 unlock 后按名称删除不安全：另一个进程可能已经打开同一载体并等待 byte-range lock；删除再创建会形成两把互不排斥的锁。Windows 普通锁句柄不共享 DELETE，可据此在所有旧句柄退出后独占取得当前载体，再重新认证并按句柄回收。

## 决策

1. **只回收两种导出输出锁**：ResourcePackage 与 TMX 导出 owner 可以在自身发布、readback、终端证明及既有 receipt/ledger 状态闭合后，请平台尝试回收该次输出目标族的锁载体。发布结果不明或 recovery-required 时不请求回收。TM 激活、快照、恢复和其他 persistent lock 不参与。
2. **释放与回收分开**：先完成正常 unlock/close，再在仍受 rooted parent 约束的目标名字上尝试 `READ|WRITE|DELETE`、share-none 的已有文件打开。不得扩大普通 LOCK profile 的 share mask，不使用先 unlink 再创建、DeleteOnClose 或锁文件迁址。任何活 holder、已打开的 waiter 或其他不兼容句柄都会阻止独占打开；平台不得等待它们退出来伪造即时清理保证。
3. **重新认证当前协议载体**：回收授权来自新取得且一直存活的独占句柄。平台重验 rooted containment、regular/single-link、named/live identity、当前 exact `ProtocolControlLockSecurityV2` 和完整 canonical family payload，终端再证明后按该句柄标记删除并关闭。未知、空、prefix、内容/安全事实不符或 namespace 漂移均保留。已关闭旧句柄的 FileId 不能授权回收；本协议也不声称原 creator 文件一直连续存活。完整同族且符合当前安全合同的闲置载体属于可重新认证的协议控制文件，不承载业务正文或恢复状态。
4. **清理不改发布结果**：回收是有界、非阻塞的尽力动作。目标不存在视为无需回收；繁忙、无法证明、删除或 close 结果不明不推翻已闭合的导出 receipt，也不掩盖原始发布/恢复失败。不能把无法证明的 residue 报成已删除。终止或异常留下的锁不构成新业务 authority，后续仍经既有初始化/加锁合同处理。
5. **新旧版本兼容边界**：旧版本已打开的持有者和等待者仍由原有无 DELETE share 句柄保护。旧版本恰好处于初始化关闭与普通打开之间时，回收可能使其后续打开明确失败；允许重试整个 acquire，不允许 fallback 建立第二种锁或绕过证明。新版本重新创建仍使用同一名字、family payload、安全 profile 与 byte range。
6. **平台与业务分权不变**：平台提供当前载体认证和安全回收原语；Resource/TMX owner 决定自身操作是否已终结。Qt 只消费结果，不删除锁、不调用 Win32、不签发安全证明。POSIX 路径及 frozen 的信任启动、manifest、owner 资格不因本修订改变。

## 长期约束

- 无 handle 的历史 identity、文件名模式和“导出完成”布尔值均不能单独铸造删除权威。
- 不扫描输出目录批量清理旧锁或随机临时文件；仅请求当前操作精确绑定的目标族。
- holder、opened waiter、旧初始化间隙、未知 payload/ACL/MIC、终端漂移、close/kill 及 recovery-required 是必须保留的反例。
- 输出锁回收不授权清理业务 candidate、journal、pending inventory 或其他 owner 的私有文件。

## 后果与权衡

正常无并发导出可只留下用户选择的最终文件。并发者、恢复未闭合或系统异常存在时可能保留锁；这比破坏同目标互斥更重要。旧版本在很窄的初始化间隙可能需要重新发起操作，不能承诺无失败的混合版本并发。

## 备选方案

- **永久保留所有导出锁**：拒绝作为正常完成的唯一策略；它把平台迁移新增副产物固化成用户输出合同。
- **unlock 后直接 unlink**：拒绝；已打开的 waiter 可以继续持有旧载体，形成双 writer。
- **移到 AppData 或改变旧锁的 DELETE share**：本次不采用；前者需要新的目标绑定和跨版本锁桥接，后者削弱既有并发保护。
- **按旧 FileId 删除**：拒绝；关闭后的 Windows identity 不能作为新的删除 authority。

## 取代关系

- **取代**：仅在 Windows Resource/TMX 输出 owner 已终结的精确范围内，取代 ADR-020 决策 7 与 ADR-023 决策 1 的“载体永不 unlink”限制。初始化、普通持锁 profile、exact security/payload、rooted identity 与其他 persistent lock 的约束继续有效。
- **被取代于**：None
