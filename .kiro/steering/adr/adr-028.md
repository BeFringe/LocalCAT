# ADR-028：Windows source 独立交付与普通 frozen 证明范围

- **状态**：已采纳（产品边界；新的 frozen 消费设计与发行验收尚未完成）
- **日期 / 批准日期**：2026-09-20
- **决策 owner**：LocalCAT 项目 owner
- **关联 Spec**：`windows-platform-enablement`；相邻 Core、Feature5/UI 与各业务 owner

## 背景

Windows source 的 CPython 3.14 venv、源码、轻量 launcher 和真实业务旅程已经完成。原 W3 将“用户无需安装 Python”的发行目标与 retained-source loader、定制 native entry、完整 Boot TCB 证明绑定；最小 spike 通过后，完整 Python/Qt 闭包仍带来持续扩大的证明与运行成本。这些成本不应反向阻塞已完成的 source 交付，也不能仅因已投入实现而成为普通桌面产品的永久要求。

## 决策

1. **独立交付**：source 是完整的用户自管运行时产品形态，W3/frozen 是后置、自包含发行线。source 的平台/业务验收不等待 packaged E2E；两线分别记录完成状态。
2. **普通桌面信任范围**：信任用户选择安装的 LocalCAT 发行物、固定的 Python/Qt 依赖与操作系统加载基础。不承诺抵御已控制同一用户安装文件或进程的攻击者，不承诺逐事件证明第三方运行时内部生成或执行的全部代码。仍保留必要的入口、依赖和加载路径检查，避免意外消费 CWD、开发环境或未声明依赖。
3. **移除强证明前置**：普通 frozen 不再强制定制 PE/native entry、完整 pre-authority Boot TCB/动态 native closure、retained-handle exact-byte source-only loader、逐次全包扫描或第三方内部执行逐事件捕获。旧 W3 可保留为研究材料；其未通过项不自动成为新 profile 的待办。
4. **保留可验证交付**：继续要求 clean tracked 发布输入、固定依赖、构建与资源清单、无 checkout/外部 venv 依赖，以及同一候选上的真实 Qt、Project、TM、TMX、FTS5 旅程和 Core Gate 验证。普通 PyInstaller onedir/windowed 是优先探索路径；“构建成功”仍不等于“产品可用”。本决策不扩大到 onefile、安装器、签名或自动更新。
5. **保留必要权限与业务证明**：source/frozen 共用已有数据保护端口、私有 SID/ACL/MIC 检查、业务恢复及 Core Gate C/D。现有性能门限和 ADR-013 设备本地资格规则不变；资源迁移不携带 Fuzzy 授权。
6. **调整证明位置而非伪造证据**：packaged 的执行身份可以在受控构建与发行验收中建立，不再被“必须运行真实外置 `.py`”锁定。Core/Host 仍需明确绑定实际执行产物、owner roots、fixture 和运行时；不能用 `sys.frozen`、任意 PASS JSON 或旁置未执行源码代答。具体 producer/consumer 合同在后续 frozen 设计中收束，本次不宣称现有实现已支持此路径。

## 长期约束

数据访问安全、检索语义/性能与程序启动来源属于三个不同验证范围。新增运行时证明应针对声明中的风险；稳定事实优先在构建或发行阶段验证。缩小产品声明不等于接受数据损坏、错误检索或虚假的通过结果。

## 后果与权衡

普通 frozen 可以使用标准打包机制探索完整产品闭环，减少自定义运行时维护和启动成本；代价是明确放弃旧 W3 的完整执行来源与同用户替换竞态保证。已有 R4 输入端口、独立 worker、取消/关闭和构建清单按新范围择需复用，不因完成旧接口而强制保留旧 producer。此决策不把旧 W3 失败改成 PASS。

## 备选方案

- 继续把旧 W3 强证明作为唯一首发门：不采用，其成本与普通桌面交付目标不匹配。
- 关闭 Gate、削弱数据权限或借 source evidence 放行 EXE：不采用，损害了仍然需要的产品保证。

## 取代关系

- **部分取代 ADR-022**：决策 3–8、10 及相关长期约束中的完整 Boot TCB、自定义 native entry、retained-source-only execution 和强制 spike；决策 9/12 中由这些强证明派生的构建/运行限制及完整重验触发器不再适用于普通 frozen。决策 1 的 onedir/windowed 保留为优先探索形态，决策 2 的 ownership、决策 9 的构建可追溯性、决策 11 的真实 packaged E2E 和禁止伪造 capability 继续保留。
- **部分取代 ADR-023**：决策 6 及相关完整 pre-authority native closure 强制门；其 LOCK-first、MIC/security profile 和 pending publication 不变。ADR-025/027 已有取代关系不变。
- **不取代**：ADR-009/013 的 Core 语义、性能和设备资格；ADR-020/021 及后续修订中的用户数据、锁、发布和私有存储保护。
- **被取代于**：无。

## Steering 同步检查

已同步 `delivery-boundaries.md`、`product.md`、`tech.md`、`roadmap.md` 和 ADR 索引。Windows Spec 将旧 W3 Requirement 10 及 Task 7–10 标为待按此边界重新设计；source 的审批、完成事实和已提交 R4 成果保留。后续设计再映射实际受影响的 owning consumer 条款，不重开无关业务范围。
