# ADR-029：Fuzzy 时间性能报告与功能准入分离

- **状态**：草案
- **日期**：2026-10-04
- **决策 owner**：LocalCAT 项目 owner
- **关联 Spec**：`tm-storage-retrieval-index` Requirement 8；`feature5-ui-integration` Requirement 6；`windows-platform-enablement` Requirement 12

## 背景

本机完整验证中的耗时超限，不能单独说明检索算错、漏项或数据不完整。现有实现把三项时间指标与召回、内存和证据完整性共同作为 Fuzzy 功能的否决条件，导致真实执行完成且其余必要条件成立时仍无法使用。

产品允许首次或资格失配后等待 Fuzzy 验证；主体编辑与保存应先可用。本决策分别固定验证触发、等待期间的使用和完成后的准入，不取消本机验证。

## 决策

1. **触发不变**：沿 ADR-013 恢复兼容的本机资格；无资格或失配时提供显式手动重验，不自动执行 100k，不加入首次免验证或跨设备资格共享。
2. **等待不阻塞编辑**：验证在后台运行，主体编辑、保存、切段及各自条件成立的 Exact/Context 继续可用。状态观察遇发布锁争用时延期；关闭与取消沿原 owner 的提交胜负规则，不从运行态或用户偏好推断 Fuzzy 授权。
3. **仅时间失败不单独否决功能**：真实完整执行后，Core 严格复证报告、当前实际路径、来源和兼容性；只有 `EXACT_P95`、`FUZZY_P95`、`MIGRATION` 三种时间超限不参与 Fuzzy 功能的一票否决。Gate C correctness、实际路径 oracle/召回、完整结果和证据来源仍须成立；峰值 RSS `512 MiB` 暂时保持现行准入限制。未知失败项拒绝；被超时终止、取消或没有完整结果不属于时间指标超限。
4. **报告不变**：`50 ms`、`500 ms`、`120 s`、`512 MiB`、原始样本、严格重算的 `passed`、`failed_gates` 和逐路径报告保持原含义。允许使用但耗时超限时，UI 显示性能不足提示；不得改写报告为 PASS，不以时间失败推导错误检索。
5. **唯一判定与恢复**：Core evaluator、publication 一致性检查和本机 restore 使用同一准入含义。既有 fingerprint 与 Gate C evaluator 身份覆盖策略实现；策略变化使旧资格要求显式重验，不新增 profile、持久 schema 或旧失败资格升级机制。Host/Controller/Qt 只消费同一 snapshot 的安全警示投影，不建立第二授权者。
6. **发行独立裁决**：功能准入、性能报告和最终发行结论分别记录。该决策不自动批准最终发行，不放宽召回、数据保护或候选必测项，也不预填未来性能结果。

## 长期约束

- Fuzzy 验证等待保留；没有必要条件的完整证据就不开放。
- `SUCCEEDED` 仍只表示运行结果已完成发布，不能代替能力或性能判定。
- 用户关闭 Fuzzy 只能收窄已授权能力；重新开启不能绕过 Core。
- 日常建议的异步执行和取消在 Feature5/Core 原边界设计，不能由后台 Gate 或轮询修复推定已完成。

## 后果与权衡

较慢设备可以在必要验证完成后使用正确的 Fuzzy，并看到性能不足提示；性能报告继续暴露回归。首次和兼容身份改变后仍需完整本机验证，512 MiB 超限仍可使路径不可用。查询延迟原因与算法优化可以独立定位，不成为准入规则的隐含前置。

## 备选方案

- 所有性能失败继续禁止功能：不采用，时间目标与必要正确性条件需要区分。
- 首次免验证、直接复用他机资格：不纳入，超出当前产品范围。
- 放宽时间数值或把失败报告改为通过：不采用，会损失真实性能事实。
- 同时放开 RSS：延期，本次保留现行限制。

## 取代关系

- **拟部分取代 ADR-013**：决策 4/5 的成功发布与恢复不再隐含三项时间门必须全通过；“后果与权衡”中的性能硬门全通过前提按本决策解释。决策 1–3、6–10 以及设备来源、兼容性、原子发布和唯一 Core authority 保留。
- **拟部分取代 ADR-028**：决策 5 对现行性能准入的引用，仅在三项时间指标对功能的否决作用上按本决策接续。普通发行、数据保护和构建边界不变。
- **不取代**：ADR-009/011 的 authority 与消费者边界、其他数据发布及恢复协议。
- **被取代于**：无。
