# ADR-033：稳定本机目录中的 TM 资源事务与外部在线替换边界

- **状态**：草案
- **日期**：2026-10-12
- **决策 owner**：LocalCAT 项目 owner
- **关联 Spec**：`tm-storage-retrieval-index`、`windows-platform-enablement`、`language-resource-portability`、`feature5-ui-integration`；下游 `cross-device-sync-plugin`、`rpy-project-codec`

## 背景

TM 是应用级资源家族，包含配置源、canonical 数据库、manifest 与恢复文件。SQLite 使用期间移动或替换家族目录不是正常导入步骤；退出后的迁移和运行中的外部命名变更具有不同前提。持有原目录对象与配置路径仍指向原目录，是两类事实。

POSIX 的 retained directory authority 可约束应用自己的文件操作，却不会自动改变标准 SQLite 驱动按路径管理主库与日志的方式。对稳定本机目录的正常使用、协作替换和崩溃恢复应继续提供完整事务；把该要求扩成任意非合作同用户进程竞争下的全时序零副作用，会引入不同的 I/O、锁和维护成本。

## 决策

1. **支持的正常使用**：在受支持的稳定本机目录中，保留 TM create/replace、查询、确认写回、导出、冷重开和 LocalCAT 自己协调的并发、替换及崩溃恢复。成功对应完整资源版本、最终注册信息和真实结果；自身漏锁、错误重绑和不完整恢复不能归类为外部不支持行为。
2. **外部在线替换边界**：使用期间由应用外部移动或替换活动 TM 目录、替换活动数据库或直接干预内部数据库／事务恢复文件不受支持。配置 JSONL／manifest 的外部内容变化仍按既有 `SOURCE_DIVERGED` 合同处理；canonical 与其家族位置仍可证明时保留原 Lookup/Update 能力，逐文件异常仍按原严格规则拒绝。不承诺所有时序均能检测，亦不承诺 SQLite 内部已发生写入、回滚、关闭或日志访问零副作用。内部操作边界已可观察的失效必须拒绝；检查间窗口及 ABA 不被描述成已消除。
3. **资源级停止**：检测失效后停止该资源的新查询、写回、导入及发布，不刷新旧授权、不立即接管同路径副本、不签发未经闭合的成功。保留已有恢复事实，区分可证明的 prior、已发布但位置失联及结果不明；不猜测删除日志、递归清理或盲目覆盖。仍有效的其他资源和项目编辑／保存按各自状态继续；TM 写回失败与项目保存结果分别呈现。
4. **保留现有事务技术**：复用标准 SQLite 驱动、Core coordinator、stage/seal/activation/recovery 状态机及现有持久格式。通用 backend 与 Windows 专用恢复能力分别组合；POSIX 不通过清空 backend 绕过 root/W1/stage 上下文。SQLite 生命周期、原始文件观察、应用发布和失败收尾共同服从同一资源家族协议。
5. **目录和发布职责**：平台提供对原 retained root 与配置位置关联的内部复证；业务只消费 opaque 结果，不获取 raw FD，不解码平台 opaque identity。已有命名链被同字节副本替换不能续接旧授权。应用自己的候选、manifest、备份、日志及清理继续使用原 root 下的受控操作；POSIX sealed stage 交接保持既有同对象约束，不靠复制后冒充原对象。
6. **检查不是资格**：配置位置复证是单次操作和生命周期中的内部检查，不新增验证按钮、长基准、资格登记或持久位置证明。不将前后身份检查宣称为 SQLite 内部全部 I/O 的目录绑定，不修改 Fuzzy 准入含义。
7. **输入保护保留**：恶意包、路径穿越、链接、特殊文件、摘要/计数篡改、preview stale 和已观察身份失效继续拒绝。外部在线替换的范围限定不豁免正常输入验证，也不削弱 Windows 现有句柄和发布保护。
8. **迁移与后续同步**：资源包导出/导入及释放全部使用者后的正常迁移复用本机事务入口。迁移使用一致包或 owner 批准快照，经目标本机 validate/preview/apply；不直接复制活动 SQLite、日志、stage 或设备资格。停止进程不等于已完成 pending/hot-journal 恢复。既有外部/default TM 路径不静默搬迁。
9. **交付与有限扩展**：Windows 保持普通 frozen，Mac/Linux 保持 source。本范围不引入 VFS、驱动迁移、额外 frozen 或新平台层。若最小方案无法覆盖某个受支持正常场景，先说明该场景、具体缺口及残余窗口，再裁决有退出条件的有限实验；外部在线替换的强反例不自动成为新增架构的实施授权。
10. **POSIX TM 的命名与后续 SQL 阶段**：允许数据库命名在对应的既有 durable owner phase 完成并复证后结束其 publication；这不是整个资源激活成功。若随后仍需合法 SQL 修改，同一 root／家族 lease 必须持续，且在关闭 publication 前以同时存活的身份比较交给同对象 mutation guard，覆盖后续 SQL 及收尾。不能在 pending 内更改预先证明的内容、关闭后重绑续接 pending，或把不明阶段报为成功。guard 只保留对象和复证位置，不宣称绑定 SQLite 内部 I/O；后续业务 phase、失败与恢复仍属原 owner。此限定不改变 Windows 或其他发布消费者的生命周期。

## 长期约束

Core 独占资源 generation、SQL 事务、lease/drain、内容证明、receipt 和恢复状态；平台独占本机文件、命名和进程锁原语；ResourcePortability 复用 Core 事务；UI 只消费资源状态。正常失败与外部命名失效分开表达。跨重启继续使用现有资源/lineage/receipt 规则，历史 inode 或路径不能成为新授权。

## 后果与权衡

该边界保留开箱即用所需的正常数据保护和跨设备包交换，并避免为非合作在线目录搬动建立完整自定义 SQLite I/O 层。代价是需要明确告知用户：活动 TM 目录不能被外部在线移动或替换；此类操作造成的不确定状态可能需要从一致快照恢复，重新打开本身不保证修好。

## 备选方案

- 仅改 POSIX 分派或把 backend 设为 None：不能闭合同资源生命周期、配置位置与应用发布，不采用。
- 自建 VFS／迁移驱动：不属于本次产品范围；只有具体新增需求和有界实验支持后再裁决。
- 永久单进程独占每份 TM：不作为默认行为变化；若正常多进程接线确有未闭合问题，另行说明产品影响。
- 静默迁移所有 source/default TM 到托管目录：改变已有路径和邻接合同，不采用。

## 取代关系

- **部分限定 ADR-020 决策 2、12**：对 POSIX stock SQLite 的内部主库/日志 I/O 明确稳定命名空间前提，不从 retained root 推导内部 syscall 全绑定；应用 rooted 操作及 Windows 合同保持。决策 8 的非 CAS 边界继续有效。
- **限定 ADR-020 决策 9 的 POSIX TM 子阶段**：数据库命名 publication 的 durable owner commit 可为原状态机中已闭合的命名 phase，随后依决策10交接给同对象 SQL mutation guard；不要求命名 publication 跨越会改变数据库字节的后续 SQL。pending 的 retained readback、内容不变与 terminal 检查不变，整个 activation 成功仍要求全部业务 phase 闭合。
- **限定 ADR-007 决策 2、4 的可用性前提**：legacy 或 last-known-good 仅在其资源绑定和内容仍可证明时可供查询；外部位置失效时停止该资源，不自动回退可疑源。
- **澄清 ADR-008 决策 6**：已观察绑定失效继续 fail closed；不由该表述推导 stock SQLite 活事务面对任意外部替换时无内部副作用。正常发布、seal 和 lease 隔离不变。
- **保持 ADR-016、ADR-025、ADR-029、ADR-031**：冷重开权威规则、Windows 普通耐久、Fuzzy 准入和整包同步所有权不变。
- **被取代于**：无。
