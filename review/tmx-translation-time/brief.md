# 译文保存时间与 TM／TMX 日期往返 Brief

状态：后续方向预留，未进入 R/D/T 审批，不授权实施。默认在多句 TL 与完整候选主线贯通后排期；不依赖结构合并器完成，不扩展当前 RPY 交付。

## 目标与范围

记录译文实际保存／更新的时间，在 TM／TMX 往返中保留有来源依据的日期，并在编辑模式右侧语言资源栏的每个匹配候选中显示。时间用于理解记忆来源与新旧，不表示编辑耗时，不改变相似度、匹配类型、排序或准入。

覆盖本地保存事件、日期导入与持久化、TMX 导出和候选展示。内部字段名称、TU／TUV 属性及自定义 prop 的选择由后续 Design 决定，不固定为 `translation_date`，不新增全量审计时间线。

## 关键行为

本地实际保存成功的译文条目记录该次保存时间；未变条目不因一次全项目保存统一刷新。保存失败不产生虚假的成功时间，结果不确定时由原保存／恢复 owner 判定。文本修改、确认状态变更和重新确认是否分别更新时间，须在正式设计中明确；不以每次按键、浏览或读取作为保存事件。

候选记忆的原有日期与采用该候选后本项目的保存时间是不同事实。项目保存和 TM 写回沿用各自提交点，不为时间一致新建跨资源事务，也不宣称项目未成功保存的内容已持久化。多句作为一份完整译法记录组级时间，不把单句时间猜测为所有子句各自的历史。

时间统一按 UTC 保存，UI 按显示时区呈现并可查看完整日期及来源。缺失或非法日期不以导入时间、文件修改时间、使用时间或当前时间补造；正文有效时沿既有导入策略保留，日期显示未知或给出有界提示。

导入先区分 TU、所选目标 TUV 与 header 的日期作用域，以及创建、修改、工具特定保存时间的语义。无法确定的原始日期保留其原义，不自动解释为译文最后修改时间；候选 UI 应区分已知保存／更新时间、仅创建日期和未知。工具标识是解释线索，不是日期真实性证明。

TMX 导出读取已经保存的时间事实，不在导出时刷新日期；相同内容和元数据应保持确定性。支持的日期及自定义属性须在 reader → importer → TM／项目快照 → writer → 冷重读之间闭合。已有未知 prop 继续按原规则保留，相似度测试期望不参与实际评分。

## Owner 接缝与待定事项

Project 定义译文保存事件及项目内时间；TM 定义记忆写回和候选日期事实；Parser 只解析有界的日期属性／metadata；TMX owner 定义作用域、来源映射、序列化与损失提示；Controller／Qt 展示日期而不自行推断。各 owner 复用既有持久化和恢复机制。

正式设计应裁决：确认／重确认的事件口径、项目保存与 TM 写回的时间传播、导入日期的选择和来源标注、组级粒度、标准属性与自定义 prop 的映射，以及旧记录缺失字段的兼容方式。不预建通用时间元数据框架，不要求历史记录补齐不存在的日期。

## 启动条件与完整验证

主线的组模型、候选 DTO 和实际保存点稳定后，形成精确的 owning R/D/T；时间项可以独立于主动结构编辑和源更新调和推进。

代表性旅程：导入一条有已知日期和一条无日期的记忆 → 查询并显示原候选日期 → 采用后编辑、成功保存当前译文 → 保存冷重开 → 写回并导出 TMX → 冷重读核对日期语义。覆盖未变项目保存、失败／不确定保存、重新确认、UTC 显示、重复导出及普通文本／有序组兼容，不以给所有条目写当前时间代替日期往返。
